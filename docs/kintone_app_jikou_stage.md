# kintone アプリ仕様: 時効案件進行（JIKOU-STAGE-APP-1・QUEUE-2026-10-20-HI I-4'）

大野／CU がアプリを作るための仕様（欄コードまで）。コード側（`hub/jikou_stage.py`）はここに書いた**欄コード・状態名・アクション名**を
そのまま参照する。変更するときは両方を同時に直す。スマホ 1 画面で「電話番号・依頼者氏名・生年月日・契約番号」が収まる欄順にする。

大野裁定: 時効の確認と依頼者への報告はこのアプリ 1 画面で完結。大野が押すのは **「時効確認済にする」ボタン 1 回＝承認**。
送る文言は承認台帳の固定文のみ。

## 1. 基本

| 項目 | 値 |
|---|---|
| アプリ名 | 時効案件進行 |
| 1 レコード | 案件（App 21 のレコード）× 債権者（枠 1〜3） |
| 作成 | ボットが受任時に債権者ごとに作成（依頼者情報を App 21 から転記。以後は App 21 が正・本アプリの依頼者欄は電話時の本人特定用） |
| 環境変数 | `JIKOU_STAGE_APP_ID`（アプリ ID）・`JIKOU_STAGE_API_TOKEN`（API トークン: レコード閲覧・追加・編集）・`JIKOU_STAGE_WEBHOOK_SECRET`（Webhook URL の秘密部分・`python -c "import secrets; print(secrets.token_hex(32))"`）・`JIKOU_CONFIRM_GRACE_MIN`（取消猶予・既定 10・要大野確認）・`JIKOU_CONFIRM_DUE_DAYS`（確認漏れ閾値・既定 7・要大野確認） |

## 3. プロセス管理

| 状態 | 誰が進める | 次のアクション（アクション名＝ボタン表示） |
|---|---|---|
| 受任（初期） | ボット | 入金確認にする → 入金確認 |
| 入金確認 | ボット | 発送済にする → 発送済 |
| 発送済 | ボット | 回答待ちにする → 回答待ち |
| 回答待ち | **大野** | **時効確認済にする** → 時効確認済 ／ **不成立にする** → 不成立 ／ 保留にする → 保留 |
| 時効確認済 | 大野（取消）／ボット | 回答待ちに戻す → 回答待ち（猶予内なら送らない）／ 報告済にする → 報告済（ボット・送信後） |
| 不成立 | 大野（取消）／ボット | 回答待ちに戻す → 回答待ち ／ 報告済(不成立)にする → 報告済(不成立)（ボット・送信後） |
| 報告済 ／ 報告済(不成立) | ボット | 完了にする → 完了（案件の全債権者が報告済になったとき） |
| 保留 | 大野 | 回答待ちに戻す → 回答待ち |

- 作業者（assignee）は設定しない（誰でも押せる・押した人が「更新者」として記録される）。
- **大野が押すのは「時効確認済にする」「不成立にする」の 2 つ**（と取消の「回答待ちに戻す」）。他はボットが写しで進める。
- 状態名・アクション名は上の表の**逐語**（全角括弧「報告済(不成立)」は半角括弧）。

## 4. Webhook

| 項目 | 値 |
|---|---|
| 通知 | 「プロセス管理のステータス変更」のみ |
| URL | `https://jikou-line-bot-production.up.railway.app/hooks/kintone/jikou-stage/<JIKOU_STAGE_WEBHOOK_SECRET の値>` |
| 動き | 時効確認済／不成立 → 猶予 `JIKOU_CONFIRM_GRACE_MIN` 分の後に処理。回答待ち → 猶予中の予約を取消。他は無視 |
| 認証 | URL の秘密部分（不一致は 401・送信ゼロ）。アプリ ID も照合 |

## 5. 一覧（スマホ用）

| 一覧名 | 条件 | 並び | 表示欄（左から） |
|---|---|---|---|
| 回答待ち（発送日順） | ステータス = 回答待ち | 通知発送日 昇順 | 債権者電話番号・債権者名・氏名・生年月日・契約番号・通知発送日 |
| 確認漏れ | ステータス = 回答待ち かつ 回答受領日 ≤ 今日 − `JIKOU_CONFIRM_DUE_DAYS` 日 | 回答受領日 昇順 | 同上＋回答受領日 |
| 今日やること | ステータス in（回答待ち, 時効確認済, 不成立）かつ 要対応 = 要対応 または 回答受領日 ≠ 空 | 更新日時 降順 | 債権者電話番号・債権者名・氏名・ステータス・要対応理由 |

## 6. ボットの動き（要約）

1. **受任**: App 21 が受任になった案件について、債権者ごとにレコードを作成（30 分ごとの走査・結果記録の保存時にも）。
2. **写し**: 入金済み→入金確認、発送日→発送済、回答日→回答待ち（前にしか進めない・人の状態には触れない）。
3. **時効確認済**（大野のボタン）: 猶予後に (a) 結果記録を成立で保存 → (b) 完了報告書 PDF → (c) 固定文 R-1＋本人専用 URL（72 時間）を
   依頼者へ LINE 送信（人による明示送信経路・台帳必須）→ (d) 報告済へ・送信日時と版番号を写す。(b)(c) 失敗は「要対応」＋業務 LINE 1 通。
4. **不成立**: 固定文 R-3 → 報告済(不成立)。
5. 全債権者が報告済／報告済(不成立) → 固定文 R-2 を 1 通 → 全て 完了。

固定文 R-1〜R-3 は `hub/jikou_stage_texts.py`（要承認・承認台帳に載るまで送らず要対応）。
