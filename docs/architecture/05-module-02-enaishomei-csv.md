# 05. モジュール2: e内容証明 差込差出し用CSV出力

日本郵便「e内容証明（電子内容証明サービス）」の**差込差出し**機能向けに、
本文 Word ファイルと差込 CSV を公式仕様準拠で生成する。

## 0. 前提と自動化境界

- e内容証明は Web サイト上で「本文 Word ファイル + 差込用 CSV」をアップロードして
  複数宛先へ一括差出しする。**公開 API は存在しない**
- したがって自動化境界は次のとおり:
  - **システムが行う**: 本文 docx 生成・差込 CSV 生成・公式仕様バリデーション・
    承認フロー・成果物一式（zip）の添付
  - **人が行う**: 承認後、成果物をダウンロードして e内容証明サイトにアップロード・差出し、
    差出し完了後に発送ステータスを `発送済` に手動変更（2操作のみ）
- 仕様の正本は日本郵便「電子内容証明サービスご利用ガイド」（差込差出し編）。
  **T5-1（仕様確定スパイク）で最新版を取得し、本書 §2 の表を確定させてから実装する**

## 1. フロー

```
[起票トリガー] CloudSign 締結 Webhook（既存 cloudsign_webhook が App 21 status=受任 に更新）
   に増設: 受任時に App 30 へ「e内容証明（時効援用通知）」下書きを自動起票
   ├─ 宛先: 業者マスタから 問い合わせ業者名 で検索（住所・郵便番号）
   └─ 業者マスタに宛先が無い → 要確認 遷移 + LINE 警報（宛先を人が補記→再処理）
   ※ 手動起票（アプリアクション）も可（複数業者への一括差出し等）
[prepare]（Railway 自動）
   1. 本文 docx 生成: docx_templates/jikou/内容証明_時効援用通知.docx に差込（§3）
   2. 差込 CSV 生成（§2。宛先リストは チャネル固有データ）
   3. バリデーション（§4）→ NG はエラー遷移 + 警報
   4. 「差出し用一式.zip」（本文.docx + 差込.csv + 手順メモ.txt）を成果物に添付
   5. → 承認待ち + 弁護士 LINE 通知
[承認] 弁護士が本文・宛先を確認 → 承認済
[dispatch] 外部APIなし（manual_mailing）。→ 発送処理中 とし、
   管理者 LINE に「e内容証明サイトへのアップロード待ち」を通知
[差出し] 人がアップロード・差出し → 発送ステータスを 発送済 に手動変更
   → 返送想定なし → 完了（e内容証明の謄本・配達証明は郵送で事務所に届く。
     受領記録が必要なら M5 のスキャン受領で「その他」として取り込む）
[監視] 発送処理中 のまま N 日（既定3日）経過 → 日次ジョブが LINE 警報（アップロード忘れ検知）
```

## 2. 差込 CSV 仕様（T5-1 で公式ガイドに合わせて確定）

設計時点で確定している要件（公式ガイドで検証・確定すること）:

| 項目 | 設計値（要確認） |
|---|---|
| 文字コード | Shift_JIS（CP932） |
| 改行コード | CRLF |
| 列構成 | 宛先ごとの差込フィールド（受取人氏名 / 郵便番号 / 住所1〜3 等）。**列順・列名は公式テンプレート CSV に完全一致させる** |
| 住所分割 | 1行あたりの最大文字数制限に合わせて住所を分割（全角換算） |
| 使用可能文字 | JIS 第1・第2水準。環境依存文字・外字は差出しエラーになるため事前検出する |
| 宛先件数上限 | 公式ガイドの上限に従う（超過時は複数レコードに分割起票） |

実装は `channels/enaishomei.py` 内に閉じる（CSV 列の知識を hub/ に漏らさない）:

```python
def build_sashikomi_csv(recipients: list[Recipient]) -> bytes  # CP932 エンコード済み
def validate_text_jis(text: str) -> list[str]                  # 使用不可文字の一覧を返す
```

## 3. 本文テンプレート（時効援用通知）

`docx_templates/jikou/内容証明_時効援用通知.docx` を新規作成（弁護士監修の文面）。
差込プレースホルダ:

| プレースホルダ | ソース |
|---|---|
| `{{日付}}` | 発送日（和暦・`to_wareki`） |
| `{{差出人_氏名}}` `{{差出人_住所}}` | config の事務所固定情報（弁護士名義） |
| `{{受取人_業者名}}` | 業者マスタ（差込フィールド側。CSV 差込と docx 差込の対応関係は T5-1 で確定） |
| `{{依頼者氏名}}` | 案件アプリの顧客名 |
| `{{債権特定情報}}` | チャネル固有データ（契約番号・借入時期等。App 21 の `借入時期_テキスト` 等から組み立て） |

- e内容証明の**本文書式規定**（用紙サイズ・余白・ポイント数・ページ数上限）は
  テンプレート側で満たし、`validate_template` + ページ数チェックで検証する

## 4. バリデーション（prepare 時。NG はエラー遷移 + LINE 警報）

| 検査 | NG 時の警報文言（要旨） |
|---|---|
| JIS 外文字（宛先・本文差込値） | 対象文字と位置を列挙「宛先の文字を修正してください」 |
| 住所・氏名の文字数上限超過 | 分割・短縮の依頼 |
| 宛先の郵便番号形式（7桁） | 業者マスタの修正依頼 |
| 本文ページ数上限超過 | テンプレート・差込値の見直し依頼 |
| 業者マスタに FAX/住所どちらも無い | 宛先ソースの登録依頼 |

## 5. チャネル固有データ（JSON スキーマ）

```json
{
  "recipients": [
    {"業者名": "アコム株式会社", "郵便番号": "564-0063",
     "住所": "大阪府吹田市江坂町2-3-35", "業者マスタレコードID": "12"}
  ],
  "債権特定情報": {"契約番号": "不明", "借入時期": "平成20年頃", "最終返済": "平成24年頃"},
  "謄本受取方法": "郵送"
}
```

## 6. テスト観点

- CSV: CP932 エンコード・列順（公式テンプレとのゴールデンファイル比較）・住所分割・
  JIS 外文字検出（`髙` `㈱` 等の代表ケース）
- docx: プレースホルダ全差込・和暦変換・ページ数チェック
- フロー: CloudSign 締結 → 自動起票（既存 `test_cloudsign_webhook.py` を拡張）、
  業者マスタ未登録 → 要確認遷移
- アップロード忘れ監視ジョブ（日付固定モック）
