# 02. kintone アプリ設計

新設3アプリのフィールド定義と、既存 App 21 / 28 / 29 との関係を定義する。

> アプリ番号 30 / 31 / 32 は本設計書内の**仮番号**。実際のアプリIDは kintone が採番するため、
> コードは既存方式どおり**環境変数から注入**する（アプリ番号のハードコード禁止。
> 既知の例外は main.py `/webhook/stripe` の `"app": 21` で、これは修正対象）。

## 1. アプリ全体マップ

| アプリ | 状態 | 役割 | ハブとの関係 |
|---|---|---|---|
| App 21 案件（時効援用） | 既存 | 時効援用ユニットの案件マスタ | 発送管理から案件参照される（片方向） |
| App 28 チャットログ | 既存 | LINE 会話ログ | 変更なし |
| App 29 承認キュー | 既存 | LINE 返信の承認 | **変更なし**。仕組み（状態+冪等+Webhook）だけを App 30 が一般化して継承 |
| 業者マスタ | 既存 | 債権者（業者）の連絡先。FAX番号・住所を保持 | M2/M3 の宛先ソース。アプリID・フィールドコードの実確認が必要（`kintone_業者マスタ.csv` がエクスポート） |
| 相談カード / 戸籍 / 通帳 / 不動産 | 既存 | `/scan` `/ocr/fixed-asset` の登録先 | M5 が分類駆動で登録先を選ぶ（既存構成を包含） |
| **★App 30 発送管理** | 新設 | 全チャネル共通トランザクション台帳・承認UI | ハブ中核 |

## 2. ★App 30 発送管理（ハブ中核）

1レコード = 1件の対外発送（または受領）トランザクション。
全チャネル共通フィールド＋「チャネル固有データ」(JSON) の構成とし、
チャネル追加でアプリ構造を変えない。

### 2.1 フィールド定義

#### 共通・案件参照

| フィールドコード | 型 | 選択肢 / 形式 | 用途 |
|---|---|---|---|
| `ユニット種別` | DROP_DOWN | 時効援用 / 相続放棄 / 相続一般 / 補助金 | 拡張ポイント。新ユニット＝選択肢追加 |
| `チャネル` | DROP_DOWN | 職務上請求 / e内容証明 / FAX / 送付案内 / スキャン受領 | ディスパッチャの振り分けキー |
| `方向` | DROP_DOWN | 発送 / 受領 | 一覧・集計用（スキャン受領のみ「受領」） |
| `案件アプリID` | SINGLE_LINE_TEXT | 例: `21` | 案件参照4点セット。案件アプリの構造に依存しない |
| `案件レコードID` | SINGLE_LINE_TEXT | | 〃 |
| `顧客名表示用` | SINGLE_LINE_TEXT | | 〃（一覧で人が読むため。起票時にコピー） |
| `件名` | SINGLE_LINE_TEXT | 例: `受任通知FAX（アコム）` | 一覧・承認通知の表示用 |

#### 状態機械（01-overview §4 参照）

| フィールドコード | 型 | 選択肢 / 形式 | 用途 |
|---|---|---|---|
| `発送ステータス` | DROP_DOWN | 下書き / 承認待ち / 承認済 / 発送処理中 / 発送済 / 返送待ち / 完了 / エラー / 却下 / 要確認 | 状態機械の現在状態。`要確認` は M5 受領の未確定専用 |
| `実行済み` | RADIO_BUTTON | no / yes（初期値 no） | 冪等ガード。App 29 `送信済み` の一般化 |
| `承認者コメント` | MULTI_LINE_TEXT | | 弁護士が承認時に記入（任意） |
| `却下理由` | MULTI_LINE_TEXT | | 却下時に記入 |
| `エラー詳細` | MULTI_LINE_TEXT | | 失敗時に Railway が書き込む（警報本文と同一） |
| `リトライ回数` | NUMBER | 初期値 0 | 外部 API 失敗時のリトライ管理（M3 等） |

#### 宛先

| フィールドコード | 型 | 用途 |
|---|---|---|
| `宛先名` | SINGLE_LINE_TEXT | 郵送/FAX の宛名（市区町村・業者・顧客） |
| `宛先郵便番号` | SINGLE_LINE_TEXT | |
| `宛先住所` | SINGLE_LINE_TEXT | |
| `宛先FAX番号` | SINGLE_LINE_TEXT | M3 のみ使用 |

#### 成果物・本文

| フィールドコード | 型 | 用途 |
|---|---|---|
| `成果物` | FILE | 生成した docx / PDF / CSV。**承認者はこれを開いて確認する** |
| `本文_特記事項` | MULTI_LINE_TEXT | 送付案内の特記事項（AI生成→人が編集可）、FAX 送信票コメント等 |
| `同封物選択` | CHECK_BOX | M4 用。選択肢は App 32 の `ブロックキー` と1対1（§4.2 の同期規約） |
| `チャネル固有データ` | MULTI_LINE_TEXT | JSON 文字列。請求内訳・差込宛先リスト・FAX job_id 等（§2.2） |

#### 発送・追跡・受領

| フィールドコード | 型 | 選択肢 / 形式 | 用途 |
|---|---|---|---|
| `発送日時` | DATETIME | | dispatch 成功時に Railway が記録（物理郵送は人が発送済に変更した日時） |
| `追跡番号` | SINGLE_LINE_TEXT | | レターパック等の追跡番号（M1。人が投函時に入力） |
| `返送期限` | DATE | | 発送日 + ユニット既定日数。日次ジョブが超過を監視 |
| `送達結果` | DROP_DOWN | 未確認 / 送達済 / 不達 / 返送受領 | M3 送達確認・M5 返送消込が書き込む |
| `受領ファイル` | FILE | | M5 が返送物スキャン PDF を添付 |
| `Drive_fileId` | SINGLE_LINE_TEXT | | M5 冪等キー（同一 PDF の二重登録防止） |

### 2.2 チャネル固有データ（JSON）の規約

- kintone 標準フィールドは「人が一覧・検索・承認確認で使うもの」に限定し、
  構造データ（配列・入れ子）は `チャネル固有データ` に JSON 文字列で保存する
- スキーマは各チャネル設計書（04〜08）の「チャネル固有データ」節で定義
- Railway 側は読み書き時に必ず JSON Schema 相当の検証を行い、不正なら状態を
  `エラー` にして LINE 警報（人が手で壊した場合の検知）

### 2.3 Webhook 設定（kintone 側 GUI 設定）

| イベント | URL | 発火条件（Railway 側で再判定） |
|---|---|---|
| レコード追加・編集 | `POST /hub/dispatch?token=<HUB_WEBHOOK_TOKEN>` | `発送ステータス` の値に応じて prepare / dispatch / 再処理を振り分け（03 §5） |

- App 29 と同じ方式: Webhook ボディで高速判定 → **最新レコードを取り直して再判定** → `実行済み` 冪等ガード
- ステータスごとの処理は Railway 側ディスパッチャの責務。kintone 側の設定は上記1本のみ

### 2.4 一覧（kintone 側 GUI 設定・推奨）

| 一覧名 | 絞り込み | 用途 |
|---|---|---|
| 承認待ち | 発送ステータス = 承認待ち | 弁護士の承認作業用（LINE 通知のリンク先） |
| 返送待ち | 発送ステータス = 返送待ち | 返送状況の確認 |
| エラー・要確認 | 発送ステータス in (エラー, 要確認) | 警報を受けた後の対応用 |

## 3. ★App 31 市区町村マスタ

職務上請求（M1）の宛先。1レコード = 1市区町村（の戸籍担当窓口）。

| フィールドコード | 型 | 用途 |
|---|---|---|
| `団体コード` | SINGLE_LINE_TEXT | 総務省 全国地方公共団体コード（6桁）。重複禁止設定 |
| `都道府県` | SINGLE_LINE_TEXT | |
| `市区町村名` | SINGLE_LINE_TEXT | ルックアップのキー |
| `担当部署` | SINGLE_LINE_TEXT | 例: `市民課`（初期値。実際に請求した際に実測で更新） |
| `郵便番号` | SINGLE_LINE_TEXT | |
| `住所` | SINGLE_LINE_TEXT | |
| `電話番号` | SINGLE_LINE_TEXT | |
| `FAX番号` | SINGLE_LINE_TEXT | 照会用（将来 M3 と併用可能） |
| `手数料_戸籍謄本` | NUMBER | 円。初期値 450 |
| `手数料_除籍改製原` | NUMBER | 円。初期値 750 |
| `手数料_附票` | NUMBER | 円。初期値 300（条例により異なるため実測更新） |
| `手数料_住民票` | NUMBER | 円。初期値 300（〃） |
| `備考` | MULTI_LINE_TEXT | 窓口固有の注意（小為替の指定・返信封筒サイズ指定等） |
| `有効` | RADIO_BUTTON | yes / no（合併消滅等は no） |

- **初期データ投入**: 総務省の全国地方公共団体コード一覧（CSV公開・約1,741団体）から
  `団体コード / 都道府県 / 市区町村名` を一括登録（`registry_to_kintone.py` と同じ
  チャンク一括登録方式）。住所・郵便番号・担当部署は「使った市区町村から実測値で埋める」運用
- 住所未登録の市区町村宛に起票された場合: prepare が検知して **状態は変えず（下書き維持）**
  LINE 警報「App 31 の該当レコードに住所を登録してください」→ 登録後、再保存で自動再処理
  （2026-07-03 T3-1 指示で「エラー遷移」から変更。実装は `channels/base.PrepareDeferred`。
  手数料未登録も同様。詳細は 04 §5）

## 4. ★App 32 同封物ブロックマスタ

送付案内（M4）の同封物1種類 = 1レコード。事務員がノーコードでメンテする。

### 4.1 フィールド定義

| フィールドコード | 型 | 用途 |
|---|---|---|
| `ブロックキー` | SINGLE_LINE_TEXT | **App 30 `同封物選択` CHECK_BOX の選択肢文字列と完全一致**させる識別子（例: `委任契約書2通`）。重複禁止 |
| `表示名` | SINGLE_LINE_TEXT | 送付案内 docx の同封物一覧に印字する行（例: `委任契約書　2通（ご署名・ご捺印のうえ1通ご返送ください）`） |
| `案内文` | MULTI_LINE_TEXT | 表示名に添える補足文（不要なら空欄） |
| `対象ユニット` | CHECK_BOX | 時効援用 / 相続放棄 / 相続一般 / 補助金（複数可） |
| `返送要否` | RADIO_BUTTON | 要 / 不要。「要」を含む送付は発送済後 `返送待ち` に遷移 |
| `表示順` | NUMBER | docx 内の並び順 |
| `有効` | RADIO_BUTTON | yes / no |

### 4.2 App 30 `同封物選択` との同期規約

kintone の CHECK_BOX 選択肢は静的なため、次の規約で運用ドリフトを防ぐ:

1. 同封物を追加するとき: **先に** App 30 `同封物選択` に選択肢を追加し、
   **次に** App 32 に同じ `ブロックキー` でレコードを追加する
2. 日次死活監視（既存 daily_healthcheck の拡張）が
   「App 32 の有効レコードの `ブロックキー` ⊆ App 30 `同封物選択` の選択肢」を検証し、
   不一致なら LINE 警報（= 手順1 を忘れた事務員ミスの自動検知）
3. prepare 時にも同検証を行い、未定義キーが選択されていたら `エラー` + 警報

## 7. EXPECTED_KINTONE_SCHEMA への追加

新設アプリは**作った直後に** `config.EXPECTED_KINTONE_SCHEMA` へ登録し、
日次死活監視の対象に入れる（フィールド改名・選択肢削除の事故を翌朝までに検知）。

```python
# config.py への追加イメージ（実装タスクで確定）
EXPECTED_KINTONE_SCHEMA["App 30 (発送管理)"] = {
    "app_id_env": "APP_SHIPPING",
    "token_env": "TOKEN_SHIPPING",
    "fields": {
        "ユニット種別":   {"type": "DROP_DOWN", "required_options": ["時効援用"]},
        "チャネル":       {"type": "DROP_DOWN",
                          "required_options": ["職務上請求", "e内容証明", "FAX", "送付案内", "スキャン受領"]},
        "発送ステータス": {"type": "DROP_DOWN",
                          "required_options": ["下書き", "承認待ち", "承認済", "発送処理中",
                                               "発送済", "返送待ち", "完了", "エラー", "却下", "要確認"]},
        "実行済み":       {"type": "RADIO_BUTTON", "required_options": ["no", "yes"]},
        # ... §2.1 の全フィールド
    },
}
```

- `required_options` は「コードが読み書きする値」のみ列挙（選択肢の追加は自由、削除・改名を検知）
- App 31 / 32 / 業者マスタも同様に、各モジュールの実装タスク内で追加する
