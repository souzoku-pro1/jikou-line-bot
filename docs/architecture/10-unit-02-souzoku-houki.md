### 0.2 契約順序の変更（既存設計からの差分と理由）

既存設計（souzoku-houki/01 [4]）は「CloudSign締結 + Stripe決済の**両方が揃って**受任確定」
としていたが、本正本では **決済 → CloudSign契約** の順に確定する（2026-07-03 弁護士決定）。

> 変更理由: 時効援用ユニットで実績のある順序（決済完了 → 契約 → 受任）に統一する。
> 決済先行により (a) 依頼意思の確度が高い段階でのみ契約書を発行する、
> (b) 決済Webhook（status=決済待ち→契約待ち）と CloudSign Webhook（status=契約待ち→受任）の
> 遷移が一方向の直列になり、両輪の揃い待ち（部分完了状態）の管理が不要になる。

## 3. 電話推奨度判定のロジック設計

### 3.1 危険類型（「電話強推奨」に倒す条件）

判定は**ルール一次＋Claude補助**（自由記述の解釈のみ tool use `set_phone_recommendation`）。
該当類型は App 33 `危険類型フラグ`（CHECK_BOX）に保存する。

| # | 危険類型 | 一次判定ルール（機械的） | Claude補助 |
|---|---|---|---|
| 1 | 熟慮期間の残りが短い | 社内締切日基準の残日数 ≤ 30（§7） | 日付の曖昧表現の解釈 |
| 2 | 熟慮期間の経過疑い | 死亡日_申告から3ヶ月超過、または日付が不明・曖昧（安全側） | 同上 |
| 3 | 遺産接触の申告あり or 曖昧 | 財産処分有無 = あり/不明 | 「葬儀費用に使った」「形見分けした」等のグレー記述の検出 |
| 4 | 被相続人死亡から長期間経過 | 死亡日_申告から1年超【要弁護士確認: 閾値】 | — |
| 5 | 他の相続人との紛争気配 | — （ルール化困難） | 「揉めている」「連絡が取れない」「勝手に手続きされた」等の検出 |
| 6 | 申告内容の矛盾 | 日付整合検証の2回失敗（§2.1） | 供述間の矛盾の検出 |
| 7 | 先順位放棄が絡む | 相続順位 ≠ 配偶者・子 かつ 先順位相続人の状況に「放棄」を含む | 家族関係の自由記述の解釈 |
| 8 | 依頼者が本人でない | 本人区分 ≠ 本人 | — |
| 9 | 未成年・後見関与 | 未成年後見関与 = あり | — |
| 10 | 訴訟・督促あり | 訴訟督促有無 = あり | 書類名の解釈 |

- **判定閾値は安全側**: 曖昧・不明・矛盾は該当フラグを立てる。フラグの解除は弁護士のみ

### 3.2 推奨度の算出

```
電話推奨度 = 強推奨: 危険類型 #1〜#6 のいずれか1つ以上該当
             推奨:   #7〜#10 のみ該当
             不要寄り: 該当なし
```

- 「不要寄り」でも判定結果は必ず弁護士に通知し、**スキップの最終判断は弁護士**
  （システムが自動でスキップする経路は作らない — B案の裁量スキップの実装保証）

### 3.3 弁護士通知フォーマット（【電話推奨度】）

```
【電話推奨度】相続放棄
顧客: 山田花子（案件No. 12）
推奨度: 強推奨
根拠:
・遺産接触の申告が曖昧（「葬儀代を故人の口座から支払った」）
・社内締切まで残 24日（暫定・起算点未確定）
ヒアリング要旨: 父死亡（5/20）・子・債権者2社判明・同時申述希望なし
App 33 の「電話要否」を選択してください（電話する / スキップ）。
```

- 通知経路は既存 `notify_admin_line`（時効援用側アカウントに一本化・souzoku-houki/07 §3）
- 根拠は依頼者には開示しない（引き上げ通知の設計思想を継承）

### 3.4 電話日程の調整（予約アプリなし運用）

- 「電話する」選択後、🤖 が候補日時の**下書き**を作成し App 29 承認キュー経由で送信
  （弁護士が候補を直接書き換えて承認する運用。日程確定も会話内で成立させる）
- 確定した日時は App 33 `電話予定日時`（DATETIME）に弁護士が記入（リマインドの入力）
- 🤖 前日リマインドを依頼者と弁護士の双方に送信（hub/scheduler）

## 4. 顧客対応トリアージ: 承認制/自動送信の線引き初期案

chat_responder のユニット一般化（G1）の上に、**v2.4 で確立した判断の型を移植**する。
仕組み（tool use・サーバー側ガード・承認キュー・即時定型文・危機対応・回帰テスト方式）は
共通のまま、カテゴリ集合・知識ブロック・フラグ定義をユニット別に差し替える。

### 4.1 v2.4 の判断の型の移植表

| v2.4 の型（時効援用） | 相続放棄への移植 |
|---|---|
| 一般論は正確に断言可＋ただし書き | 「死亡を知った日から3ヶ月以内に家庭裁判所へ申述するのが原則です」等の制度一般論は断言可。ただし書き「起算点（いつから数えるか）の判断は個別性が高く、弁護士が確認します」を必須化 |
| 個別見立ては条件付き＋留保必須 | カテゴリ「相続放棄見立て_条件付き」: 「お伺いした内容が正確であれば、相続放棄の申述は可能と考えられます」＋必須留保「最終的な可否は家庭裁判所の審理を経て確定します」＋依頼導線。**残日数の数値への言及はこのカテゴリでも禁止**（§4.2） |
| 誤解訂正型 | 「死亡から3ヶ月ではなく、死亡を**知った日**から3ヶ月」「借金だけ放棄して財産は相続、はできない」等の定型訂正 |
| 確認質問型 | 遺産接触のグレー記述（「片付けた」「葬儀代を払った」）に「どのような内容でしたか？」＋一般論 |
| 判断分岐提示型 | 「3ヶ月を過ぎていても、知った時期によっては申述できる場合があります。いつ頃お知りになりましたか？」 |
| 切り分け型 | 制度説明=自動／申し出=承認制（解約等）。「放棄と限定承認どちらがよいか」は選択相談＝承認制 |
| `jikou_update_flag` | **`単純承認事由フラグ`**（§4.3） |
| 危機対応の専用即時文面＋【緊急・要即時対応】 | crisis_support（希死念慮）は**文面ごと共用**。差押え切迫パニックは債権者切迫版の文面を新設（文言は【要弁護士確定】） |
| 裁判所書類の第一報→資料収集文面 | 「債権者・裁判所から書類が届いた」→全ページ写真送付依頼（文面は時効援用版を流用可） |
| 禁止語・許可リスト・必須文言ガード | サーバーガードの仕組みを共用。相続放棄の追加禁止語・費用必須文言は §4.4 |

### 4.2 相続放棄で**絶対に自動送信しない**類型（初期案）

souzoku-houki/02 §5 の保守的な線引きを継承する:

| 類型 | 理由 |
|---|---|
| 熟慮期間の残日数・「間に合うか」 | 起算点の認定は法的判断。誤った安心・誤った焦りのどちらも致命的 |
| 財産の使用・処分・保存行為の可否（「預金をおろしていい？」「家を片付けていい？」「携帯を解約していい？」） | 法定単純承認（民法921条）リスク。誤答は放棄不能に直結 |
| 起算点の個別判断（「私の場合いつから3ヶ月？」） | 同上 |
| 他の相続人・順位繰上りの相談 | 利益相反の可能性検知を含む |
| 債権者への対応指示 | 法的判断 |
| 相続放棄と限定承認・遺産分割との選択相談 | 選択の法的判断 |
| 費用交渉・クレーム・解約 | v2.4 と同じ |

### 4.3 単純承認事由フラグ（`tanjun_shonin_flag`）

`jikou_update_flag` の相続放棄版。会話履歴・今回のメッセージ・App 33 に次の事実が
現れたら true にし、**以後の見立て（相続放棄見立て_条件付き）はすべて承認制に降格**する:

- 遺産（預貯金・不動産・車・保険等）を使った・処分した・解約した・名義変更した
- 相続財産から債務を弁済した・葬儀費用等を支払った
- 遺産分割協議に参加した・署名した
- 被相続人宛の請求を相続財産から支払う意思を示した

※「触っていない」「使っていない」等の否定回答は該当しない（v2.4 の否定除外原則を踏襲）。
フラグ該当時は「状況を確認しますので、詳しい経緯をお聞かせください」の資料収集・
事実確認に接続する（誤答による誘導を避け、判断は弁護士へ）。

### 4.4 サーバー側ガード（v2.4 の枠組みに追加する相続放棄分）

| ガード | 内容 |
|---|---|
| 禁止語（追加） | 「必ず放棄できます」「絶対に受理されます」等 → 既存断定語パターンに「放棄|受理」を追加。行動指示語に「（遺産を）使って/処分して/解約して（の許可形）」を追加。否定形除外・許可リストの仕組みは共用 |
| 費用必須文言 | 「88,000円」「税込」「前払い」「分割」＋受任範囲（3社まで受理通知送付込み）を欠く費用回答は降格（固定文は §5.2） |

| 残日数言及の検知 | 返信文中の「残り◯日」「あと◯日で期限」パターンを検知したら降格（残日数の自動送信を構造的に禁止） |

## 5. 料金・受任範囲

### 5.1 料金体系（確定・変更禁止）

| 項目 | 金額（すべて税込） |
|---|---|
| 申述人1人目 | 88,000円 |
| 同一被相続人につき2人目以降 | 1人あたり 33,000円追加 |
| 支払方法 | 前払いのみ・分割不可。銀行振込またはカード決済（Stripe・デビットカード可） |

- 「同一被相続人」のグルーピング: 1申述人=1案件（App 33 レコード）の原則は維持し、
  `被相続人グループID`（§6.2）で同一被相続人の案件を束ねる。料金計算・決済リンクは
  グループ単位（例: 兄弟3人 = 88,000 + 33,000×2 = 154,000円を代表者に1リンク）
- 決済は受任前（status=決済待ち）。時効援用と同じ「前払い」方針

### 5.2 費用の固定文（サーバーガードの必須文言と1対1）

```
【費用のご案内】
・費用: 申述される方お1人目 88,000円（税込）。同じ被相続人について
  2人目以降は1人あたり 33,000円（税込）の追加となります
・お支払い: 前払いのみ（分割払いは承っておりません）
・お支払い方法: 銀行振込またはカード決済（Stripe・デビットカード可）
・費用には、家庭裁判所への申述代理と、受理後の債権者への受理通知の送付
  （3社まで）が含まれます
```

- 却下等で受理に至らなかった場合の費用の扱い（返金の有無）は【要弁護士確認】
  （時効援用は「不成立でも費用発生」を固定文に含めている。同型の一文を入れるか要判断）

### 5.3 受任範囲と追加料金

- 受任範囲（確定）: 弁護士が代理人として家庭裁判所へ申述。債権者**3社まで**は
  相続放棄申述受理通知の送付込み
- **4社目以降の単価案**: 1社あたり **5,500円（税込）**【要弁護士確認】
  （根拠: M4送付1件あたりの実費〔郵送・受理通知写し作成〕＋事務工数。
  時効援用の1社単価の1/8程度で、送付のみの役務であることと整合）
- 3社カウントは App 33 `債権者一覧` サブテーブル（§6.3）の「通知要否=要」行数で管理。
  4社目以降の行には `追加料金対象` が自動で立ち、超過分の決済確認を挟んでから M4 起票する

### 5.4 キャンセル・返金

- 申述書提出前のキャンセル可否・返金基準は【要弁護士確認】
  （時効援用は「通知発送前ならキャンセル・返金可」。相続放棄の対応する節目は
  「申述書の家裁提出前」が候補）
