# 07. モジュール4: 送付案内システム

書類郵送時の送付案内（カバーレター）と宛名ラベルを、同封物のチェックボックス選択から
同時生成する。**最初に実装するチャネル**（外部 API なし・共通基盤の実証台。09 §1 参照）。

## 0. 業務前提

- 顧客・業者・裁判所等へ書類を郵送する際、同封物一覧を記した送付案内を添える
- 同封物の種類は有限（委任契約書・住民票取得同意書・請求書・返信用封筒…）で、
  **文面ブロックは App 32 同封物ブロックマスタで事務員がノーコード管理**する
- 特記事項（「〇〇の欄にご捺印ください」等の一文）を AI が下書きし、承認時に弁護士が確認

## 1. フロー

```
[起票] 案件アプリのアプリアクション or App 30 直接作成で下書きレコード
   ├─ 宛先: 顧客（案件アプリから引き継ぎ）/ 業者 / 任意入力
   ├─ 同封物選択 CHECK_BOX にチェック（選択肢 = App 32 ブロックキー。02 §4.2）
   └─ 保存 → Webhook → /hub/dispatch
[prepare]（Railway 自動）
   1. App 32 から選択ブロックを取得（有効=yes・表示順ソート・対象ユニット一致を検証）
   2. 特記事項を AI 生成（§3）→ 本文_特記事項 に書き込み（人が承認前に編集可能）
   3. 成果物2点を同時生成・添付:
      a. 送付案内 docx（§2）
      b. 宛名ラベル PDF（hub/address_label.render_label_sheet。返信用の事務所宛面も含む）
   4. → 承認待ち + 弁護士 LINE 通知
[承認] 弁護士が docx・特記事項を確認（必要なら kintone 上で 本文_特記事項 を修正して
   下書きに戻す→再生成、または docx を差し替え）→ 承認済
[dispatch] 外部APIなし（manual_mailing）→ 発送処理中・事務員へ印刷指示通知
[投函] 事務員が印刷・封入・投函 → 発送済 に手動変更
   ├─ 選択ブロックに 返送要否=要 が1つでもある → 返送待ち（返送期限設定・M1 と同じ監視）
   └─ すべて不要 → 完了
```

## 2. 送付案内 docx テンプレート

`docx_templates/<ユニット>/送付案内.docx`。プレースホルダ:

| プレースホルダ | ソース |
|---|---|
| `{{日付}}` | 生成日（和暦） |
| `{{宛先名}}` | App 30 宛先名（敬称はテンプレート側） |
| `{{顧客名}}` `{{件名}}` | App 30 |
| `{{同封物一覧}}` | App 32 選択ブロックの `表示名`（+`案内文`）を改行結合した1文字列。`fill_template` は単純置換のため**複数行は結合済みで渡す** |
| `{{特記事項}}` | 本文_特記事項（空なら「特にございません」等のテンプレート既定文はテンプレ側に置かず、空文字差込で自然に消える構成にする） |
| `{{事務所署名}}` | config の事務所固定情報 |

## 3. 特記事項の AI 一文生成

- `claude_gateway.create_message_with_fallback` を tool use（`compose_note`）で呼ぶ:

```
入力: 件名 / 宛先種別（顧客・業者・その他）/ 同封物一覧 / 案件ステータス
出力: {"note": "1〜2文の特記事項", "confidence": ...}
禁則（chat_responder のルールを継承）:
  - 法的判断・見通しの断定禁止 / 記録にない日付・金額・進捗の創作禁止
  - 敬体。50字×2文以内
```

- **AI は加飾であり必須依存にしない**: 生成失敗（ClaudeUnavailableError 含む）時は
  特記事項を空欄にして prepare を続行する（警報も出さない。承認時に人が気付ける）。
  対外文書の品質は承認ステップで担保する
- どうせ全件承認を通るため、AI 生成分の追加リスクはない（auto_send 概念はこのチャネルに存在しない）

## 4. チャネル固有データ（JSON スキーマ）

```json
{
  "blocks": ["委任契約書2通", "返信用封筒"],
  "label_layout": "A4_2x6",
  "ai_note": {"generated": true, "model": "claude-sonnet-4-6", "edited_by_human": false}
}
```

（`blocks` は prepare 時点のスナップショット。後から App 32 を変更しても
承認済文書と成果物の整合が崩れない）

## 5. 異常系一覧

| 事象 | 検知 | 自動対応 | 警報 |
|---|---|---|---|
| 同封物未選択で保存 | prepare | エラー遷移 | ○ |
| 選択キーが App 32 に無い/無効 | prepare | エラー遷移 | ○（同期規約 02 §4.2 違反） |
| App 30 選択肢と App 32 の乖離 | 日次死活監視 | なし | ○ |
| ユニット不一致ブロック選択 | prepare | エラー遷移 | ○ |
| AI 生成失敗 | prepare | 空欄で続行 | ×（承認で人が確認） |
| テンプレート差込キー欠損 | prepare / 日次検査 | エラー遷移 | ○ |

## 6. テスト観点

- ブロック取得: 表示順ソート・無効除外・ユニットフィルタ・未定義キー検出
- docx: 同封物一覧の複数行結合差込・特記事項空欄時の見た目（ゴールデンファイル比較）
- ラベル PDF: 面付けレイアウトのスモークテスト
- AI 生成: tool use 正常系・失敗時の空欄続行（モック）
- 返送要否: 「要」混在時のみ 返送待ち に遷移する分岐
