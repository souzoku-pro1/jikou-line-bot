# 04. 遺言書（自筆証書〔法務局保管対応〕＋公正証書原案）

遺言は**本人の意思表示そのもの**であり、書類3種の中で最も人間の関与が重い。
システムの役割は「構造化ヒアリング」「様式チェック」「弁護士が確認した文案の清書用資料化」
「財産目録別紙の生成（PC 作成可の部分）」に限定する。**全文案の AI 単独生成は禁止**。

## 1. ヒアリング項目の構造化

遺言ヒアリングは対面/Zoom で弁護士が行う前提（相続放棄 02 の Bot ヒアリングは使わない。
遺言能力・真意の確認は人間の仕事）。システムはヒアリング結果の**入力フォーム（kintone）**と
チェックリストを提供する。

| 区分 | 項目 | 格納先 |
|---|---|---|
| 遺言者 | 氏名・生年月日・住所・本籍 | 案件アプリ（App 26） |
| 財産 | 財産の特定・評価 | **App 36（財産目録と完全共用）** |
| 受遺者・相続人 | 氏名・続柄・住所・生年月日（相続人以外の受遺者含む） | **App 37（続柄=受遺者を含む）** |
| 割付 | 誰に何を（相続させる/遺贈する の区分） | **App 38**（取得区分に `相続させる` / `遺贈` を追加） |
| 遺言執行者 | 指定の有無・氏名・職業（弁護士指定か） | 案件アプリに追加フィールド |
| 祭祀承継・予備的遺言・付言事項 | 自由記述（弁護士がヒアリングで記録） | 案件アプリ MULTI_LINE_TEXT |

- データ層を協議書と共用することで、「遺言→将来の遺産分割」の両場面で財産・関係者の
  入力が1回で済む

## 2. 自筆証書遺言（法務局保管制度対応）

### 2.1 「本人が自書すべき部分」と「システムが用意できる部分」の区分

| 部分 | 誰が | システムの成果物 |
|---|---|---|
| 本文（全文）・日付・氏名 | **本人が自書**（民法968条1項） | 弁護士確定済みの文案を**「清書用見本」**として docx 出力（本人はこれを見て手書きする。見本には「この紙に書かない・見本は提出しない」の注意書きを大書） |
| 押印 | 本人 | チェックリストで確認 |
| **財産目録（別紙）** | **自書不要（パソコン作成可・民法968条2項）** | App 36 から**目録別紙 docx を生成**（02 の生成部品を共用）。ただし**別紙の各頁に本人の署名押印が必要** — 署名押印欄を各頁フッターに自動配置 |
| 訂正 | 本人（方式厳格） | 「訂正しない・書き直す」を推奨する注意書き |

### 2.2 法務局保管制度の様式チェックリスト（システムが検査・出力する）

> 数値は設計時点の理解。**実装タスク（S7）で法務省の最新の様式注意事項に照らして
> 確定させる**（e内容証明 T5-1 と同じ「公式仕様確定」方式）。

| # | 様式要件 | システムの担保方法 |
|---|---|---|
| 1 | 用紙 A4・**片面のみ** | 目録別紙 docx のページ設定＋清書用見本への注記 |
| 2 | 余白: **左20mm・上5mm・右5mm・下10mm 以上** | 目録別紙のページ余白をテンプレートで固定。清書用見本にも余白ガイド枠を印刷（本人の自書用紙に敷く下敷きとして使える） |
| 3 | 各ページにページ番号（例 1/3。**余白内に書かない**） | 目録別紙は自動採番。自書部分はチェックリスト項目 |
| 4 | 複数枚でも**綴じない**（ホチキス・製本不可） | 提出前チェックリスト項目（事務員向け） |
| 5 | 目録別紙の**全ページに署名押印** | フッターに署名押印欄を自動配置＋チェックリスト |
| 6 | 消えるペン不可・鉛筆不可 | 清書用見本の注意書き |
| 7 | 本文と目録の対応（「別紙目録第1記載の不動産」等の引用整合） | 生成時に本文案の引用番号と目録の番号を機械照合 |

- 出力物: ①清書用見本（本文案・弁護士確定後）②財産目録別紙（PC 作成分・署名押印欄付き）
  ③様式チェックリスト（本人・事務員向け）④法務局保管申請の持ち物一覧（遺言書・
  申請書・本籍記載の住民票・本人確認書類・手数料等）— いずれも docx/hub 生成

## 3. 公正証書遺言（公証役場向け原案）

| 成果物 | 内容 |
|---|---|
| 原案 docx | 公証人に渡す文案: 遺言者表示・条項（割付から §2 と同じ生成ロジック・「相続させる/遺贈する」の区分）・遺言執行者条項・祭祀・予備的遺言・付言。**全文が弁護士確認済みであることが出力の前提条件** |
| 必要資料一覧 docx | App 36/37 から自動導出: 遺言者の印鑑証明・戸籍（遺言者と相続人の続柄がわかるもの）・受遺者の住民票（相続人外）・不動産の登記事項証明＋固定資産評価証明（App 36 の不動産行から物件別に列挙）・預貯金の通帳写し・**証人2名の氏名/住所/生年月日/職業**（欠格事由の注意書き付き）・本人確認資料 |
| 公証役場とのやり取り | **人（弁護士・事務員）**。メール送付等の自動化はしない（公証人との調整は定型化できない） |

## 4. 承認フロー（AI 単独生成禁止の実装）

```
ヒアリング入力（人）→ 財産・受遺者・割付の登録（02/03 と同じデータ層）
 → 条項の機械組み立て（条項マスタ差込のみ・03 §3 と同じロジック。
   付言事項・予備的遺言などの自由文は**ヒアリング記録の転記のみ**で AI 生成しない）
 → 【必須】弁護士が kintone 上で全文確認・修正 → `文案確定=yes`（弁護士のみ）
 → 文案確定後に初めて成果物（清書用見本/原案/チェックリスト/資料一覧）を生成
 → 本人への郵送は M4 送付案内（承認必須・既存設計のまま）
```

- 状態フィールド（案件アプリに追加）: `遺言方式`（自筆保管/公正証書）・`文案確定`
  （RADIO・弁護士のみ）・`遺言執行者` 等（§1 の表）
- 熟慮期間のような期限監視はない。滞留リマインド（文案確定後30日未発送等）のみ
  scheduler に登録

## 5. 人間に残す分担（明記）

| 作業 | システム | 人間 |
|---|---|---|
| 遺言能力・真意・氏名/生年月日等の本人確認 | — | **弁護士（対面/Zoom）** |
| 分割・遺贈の内容 | 割付入力の器と整合検証 | **本人の意思＋弁護士の助言** |
| 文案 | 条項マスタの機械差込＋ヒアリング記録の転記 | **全文の確認・修正・確定（文案確定=yes）** |
| 自書 | 清書用見本・余白ガイドの提供 | **本人の手書き** |
| 様式適合 | チェックリスト生成・目録別紙の様式担保・引用整合の機械照合 | 最終確認（事務員→弁護士） |
| 公証役場調整・保管申請同行 | 資料一覧の生成 | 弁護士・事務員 |

## 6. テスト観点（S 系列の完了条件用）

- 文案確定=no で成果物生成が拒否されること（AI 単独生成禁止のガード）
- 目録別紙: 余白・ページ番号・全頁署名押印欄（ページ数可変で検証）
- 本文案と目録の引用番号の機械照合（不一致で警報）
- 「相続させる/遺贈する」の区分が受遺者の続柄と整合（相続人外に「相続させる」→警報）
- 必要資料一覧: 財産構成（不動産あり/なし・受遺者あり/なし）による出し分け
