## 「既存のまま使う / 拡張する / 置き換える」総括

| 既存資産 | 扱い | 内容 |
|---|---|---|
| 相談カード（App 26） | **既存のまま使う** | 相続一般ユニットの案件アプリに昇格（フィールド変更なし・UNIT_CONFIG 登録のみ） |
| 不動産（App 25） | **既存のまま使う＋参照** | 不動産の詳細台帳として維持。財産テーブル（App 36）から元レコード参照。/ocr/fixed-asset の上書き先も維持 |
| 戸籍（App 27）・相談カード OCR | **既存のまま使う** | 財産ではないため変更なし（相続人テーブルへの将来接続のみ・01 §3） |
| 通帳アプリ | **置き換える（休眠中に）** | env 未設定で休眠中。再開時は財産テーブル直行に切替え、既存アプリへの新規書き込みは行わない（01 §4） |
| `/ocr/fixed-asset`（系統B） | **拡張する** | 現行の不動産25上書きは維持しつつ、案件紐付け・財産行転記・原本PDF添付・冪等キーを追加（02 §3） |
| `/scan`・GAS（系統A） | **既存のまま使う→T4系で置き換え** | 残高証明・登記事項証明はハブ M5（/scan/v2・DOC_TYPE_CONFIG）のエントリ追加として実装（02 §4）。現行 /scan は互換維持（architecture/08 §5 どおり） |
| `hub/docx_builder`（T0-3） | **拡張する** | 表の行複製（fill_table_rows）を追加。**新エンジンは作らない**（既存 fill_template と同居・02 §2） |
| UNIT_CONFIG | **拡張する** | 「相続一般」エントリ追加（テンプレート dir・案件アプリ=App 26） |
| App 30 要確認キュー / 承認（T1-2） | **既存設計のまま使う** | OCR 確信度低・紐付け不能の受け皿、生成書類の承認・発送（M4） |
| `ocr_to_claude.py` / `registry_to_kintone.py` | **参考実装として流用** | 登記事項証明の抽出スキーマ・フィールド対応表の下敷き（02 §4。registry の既知不整合は修正前提） |

## current-state-report「完成度の穴」の本設計での解消

| 穴 | 解消策 |
|---|---|
| 原本 PDF が kintone に残らない | 財産行（App 36）に `原本` FILE を持ち、OCR 経路が必ず添付（02 §3-4） |
| 重複投入の防止がない | `Drive_fileId`（系統A）／ファイル SHA-256（系統B・ローカル PC 経由に fileId がないため）を冪等キーに（02 §3） |
| 案件への紐付けがない | 財産行は案件参照必須。紐付け不能は登録せず要確認キューへ（02 §5） |
| GAS エラー処理なし | 本設計のスコープ外（ハブ T4 系で解消）。それまで新種別の投入は系統B・手動アップロードを推奨（02 §4） |

## 全体共通の制約（各書で個別に明記）

1. 生成エンジンは hub/docx_builder＋UNIT_CONFIG のみ（新エンジン禁止）
2. **法的判断は人に残す**: 評価方法・評価額の確定／協議書の特殊条項と最終文言／
   遺言の全文案（AI 単独生成禁止）— 線引きは各書の「人間に残す分担」節
3. 平常時人間ゼロ・異常時 LINE 警報・対外発信は承認必須（3原則の継承）
