# 03. kintone 設計

新設3アプリ。仮番号は既存採番（〜39 使用済み）の続き。
作成直後に `EXPECTED_KINTONE_SCHEMA` へ登録（既存規約）。

## 1. ★App 40 公募マスタ（1公募回 = 1レコード）

### 1.1 基本情報（jGrants API 取込ジョブが下書きを自動作成する範囲・K3）

| フィールドコード | 型 | 用途 |
|---|---|---|
| `公募キー` | SINGLE_LINE_TEXT | 一意（jGrants の公募ID or 手動採番）。重複禁止・取込の冪等キー |
| `制度名` / `公募回` | SINGLE_LINE_TEXT | 例: `小規模事業者持続化補助金` / `第18回` |
| `公募元` | DROP_DOWN | 国 / 都道府県 / 市区町村 / その他 |
| `申請方式` | DROP_DOWN | jGrants / 独自ポータル / 郵送 |
| `公募開始日` / `締切日時` | DATE / DATETIME | 締切は**時刻まで**（電子申請は当日時刻締切が通例） |
| `採択発表予定` | DATE | 目安（成功報酬のフォロー起点） |
| `補助率` | SINGLE_LINE_TEXT | 例: `2/3（賃上げ特例 3/4）`（表示用。計算はしない） |
| `上限額` / `下限額` | NUMBER | 円 |
| `公募要領URL` / `様式URL` | LINK | |
| `状態` | DROP_DOWN | 下書き（取込直後） / 準備中（要件登録中） / **公募中**（Bot 診断対象） / 締切済 / 終了 |
| `GBizID要否` / `支援機関要件` | DROP_DOWN / SINGLE_LINE_TEXT | 支援機関要件=認定経営革新等支援機関の確認書要否等（事業再構築系）。**該当時は受任判断の警告に表示**（弁護士事務所が要件を満たすかは人の判断） |

### 1.2 構造化データ（人が公募要領から登録する範囲）

| SUBTABLE | 列 | 用途 |
|---|---|---|
| `適格性ルール` | 変数名 / 演算子 / 値 / 条件区分（必須・除外・要確認） / 根拠メモ | 02 §2 |
| `必要書類` | 書類名 / 対象（法人・個人・共通） / 取得元（顧客・システム生成・事務所手配） / 備考 | 案件チェックリストの生成元 |
| `加点項目` | 項目名 / 要件概要 / 必要な追加書類 / 備考 | 04 §3 の加点チェックリスト生成元 |
| `判定テストケース` | 回答セット(JSON) / 期待判定 | 02 §4 の回帰テスト |
| `報酬設定` | 着手金額 / 成功報酬率 / 成功報酬の請求タイミング | 06。**金額は人が登録** |
| `実績報告ルール` | 期限種別（交付決定からN日・事業終了からN日・固定日） / 値 | 05 §3 の期限自動設定 |

## 2. ★App 41 補助金案件

App 33（相続放棄案件）の型を踏襲。

| フィールドコード | 型 | 用途 |
|---|---|---|
| `LINEユーザーID` / `顧客名` / `住所` / `電話番号` / `メールアドレス` | | 他ユニット共通の並び |
| `事業者名` / `事業形態` / `業種` / `従業員数` / `資本金` | SINGLE_LINE_TEXT 等 | BtoB 属性（診断回答から転記・検索用にフィールド化） |
| `status` | DROP_DOWN | 問い合わせ / 診断完了 / 受任判断待ち / 契約待ち / 決済待ち / 受任 / 資料収集中 / 計画書作成中 / 申請承認待ち / 申請済み / 採択 / 不採択 / 交付決定 / 実績報告中 / 完了 / 不受任 / 辞任 |
| `対象公募キー` | SINGLE_LINE_TEXT | App 40 参照（1案件=1公募。複数公募は案件を分ける） |
| `診断回答` / `診断結果` | MULTI_LINE_TEXT(JSON) | 02 §1・§3 |
| `GBizID状態` | DROP_DOWN | 未確認 / 未取得 / 申請中 / 取得済み |
| `書類チェック` | SUBTABLE | 書類名 / 取得元 / 状態（未・依頼中・受領・不要） / 発送管理No（H9/申述パッケージの型） |
| `事業計画データ` | MULTI_LINE_TEXT(JSON) | 04 §2 の構造化ヒアリング結果 |
| `計画書確定` | RADIO_BUTTON(no/yes) | **弁護士のみ**。申請パッケージ生成の前提条件 |
| `提出日時` / `受付番号` | DATETIME / SINGLE_LINE_TEXT | 提出記録（人が入力） |
| `採択結果` | DROP_DOWN | 未 / 採択 / 不採択（**人が入力**→以降の処理を自動発火） |
| `交付決定日` / `事業終了日` / `実績報告期限` / `社内締切日` / `提出目標日` / `残日数` / `通知済み閾値` | 05 参照 | 期日フィールド群（相続放棄 03 §2 と同名の型） |
| `成功報酬請求状態` | DROP_DOWN | 対象外 / 未請求 / 請求済 / 入金済（06） |
| `cloudsign_document_id` / `Stripe決済ID` / `入金状況` | | H8 の型 |

Webhook: `POST /hojokin/case-webhook?token=...`（合言葉+再取得+冪等の既存方式）

## 3. ★App 42 診断変数マスタ（質問バンク）

| フィールドコード | 型 | 用途 |
|---|---|---|
| `変数名` | SINGLE_LINE_TEXT | ルールが参照する識別子（例 `従業員数`）。重複禁止 |
| `質問文` | MULTI_LINE_TEXT | LINE でそのまま出す文言 |
| `型` | DROP_DOWN | 数値 / 選択 / 複数選択 / テキスト / はい・いいえ |
| `選択肢` | MULTI_LINE_TEXT | 改行区切り（選択系のみ。クイックリプライに使用） |
| `優先度` | NUMBER | 質問順・質問数上限時の優先（02 §1） |
| `依存変数` | SINGLE_LINE_TEXT | 例: `事業形態=法人` のときだけ資本金を聞く |
| `有効` | RADIO_BUTTON | |

初期データ（想定12変数）: 事業形態 / 業種 / 従業員数 / 資本金 / 所在地（市区町村） /
創業年 / 直近年度売上 / 課税所得区分 / 投資予定内容 / 投資予定額 / 賃上げ予定 / GBizID有無

## 4. UNIT_CONFIG・環境変数

```python
UNIT_CONFIG["補助金"] = {
    "case_app_env": ("APP_HOJOKIN", "TOKEN_HOJOKIN"),
    "customer_name_field": "顧客名",
    "customer_addr_field": "住所",
    "channels": ["送付案内", "スキャン受領"],
    "template_dir": "hojokin",
    "line_channel_env": ("HOJOKIN_LINE_CHANNEL_SECRET", "HOJOKIN_LINE_CHANNEL_ACCESS_TOKEN"),
    "hearing_statuses": {"", "問い合わせ"},
    "post_engagement_statuses": {"受任", "資料収集中", "計画書作成中", "申請承認待ち",
                                 "申請済み", "採択", "交付決定", "実績報告中", "完了"},
}
```

| 環境変数 | 説明 |
|---|---|
| `APP_KOBO_MASTER` / `TOKEN_KOBO_MASTER` | App 40 公募マスタ |
| `APP_HOJOKIN` / `TOKEN_HOJOKIN` | App 41 補助金案件 |
| `APP_SHINDAN_VARS` / `TOKEN_SHINDAN_VARS` | App 42 診断変数マスタ |
| `HOJOKIN_LINE_CHANNEL_*` / `HOJOKIN_WEBHOOK_TOKEN` | LINE チャネル・案件 Webhook |
