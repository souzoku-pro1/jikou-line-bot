# 06. 書類生成：申述書・照会書回答案・上申書

`hub/docx_builder`（fill_template + resolve_template）と UNIT_CONFIG
（`template_dir: "houki"`）にそのまま乗せる。**新しい生成エンジンは作らない。**

## 0. 共通規約

- 配置: `docx_templates/houki/<種別>.docx`（規約ベース・ハブ 03 §6）
- プレースホルダは `{{...}}` 単純置換（既存 fill_template の制約に合わせ、
  複数行データは Railway 側で改行結合して1プレースホルダに渡す）
- テンプレートの雛形文面は**弁護士が作成・監修**し、システムは差込のみ行う
- `validate_template` を日次死活監視に登録（プレースホルダ欠落の翌朝検知）
- 生成物はすべて App 30（発送管理）の成果物として添付され、
  **承認済を経ずに外へ出る経路はない**（ハブ状態機械で保証）

## 1. 相続放棄申述書（`houki/相続放棄申述書.docx`）

裁判所の定型書式に準拠したレイアウトを docx で再現（家裁配布の記載例に基づき弁護士が雛形化）。

| プレースホルダ | ソース（App 33） |
|---|---|
| `{{管轄裁判所}}` | 管轄裁判所 |
| `{{申述人_氏名}} {{申述人_住所}} {{申述人_生年月日}} {{申述人_本籍}}` | 顧客名 / 住所 / 生年月日 / 申述人戸籍（M5 受領データから転記） |
| `{{被相続人_氏名}} {{被相続人_最後の住所}} {{被相続人_本籍}} {{死亡日}}` | 被相続人各欄・死亡日（**確定値**。戸籍受領後に弁護士確認済みの値） |
| `{{続柄}} {{相続順位}}` | 続柄 / 相続順位 |
| `{{相続の開始を知った日}}` | 起算日_確定（**起算点確定済=yes が生成の前提条件**） |
| `{{放棄の理由}}` | 定型選択肢＋補足（ヒアリングの負債概況から Claude が下書き→弁護士確定） |
| `{{相続財産の概略}}` | 財産概況・負債概況から整形 |
| `{{代理人_表示}}` | config 事務所固定情報（弁護士名義） |

- **生成の前提条件**（満たさない場合は生成せず警報）: 起算点確定済=yes、
  受任判断=受任可、書類チェックリストの戸籍系が「受領」
- 同時申述（兄弟複数人）は申述人1人＝1案件レコード＝1通で扱う（案件を分けることで
  熟慮期間・承認・発送を個別管理できる。家族はまとめて1発送にせず個別起票）

## 2. 照会書回答案（`houki/照会書回答.docx`）

裁判所からの照会書（質問事項書）への回答書面。照会書は M5 が受領・分類（doc_type=裁判所書類）。

生成フロー:
```
M5 受領 → App 33 紐付け・status=照会書対応
 → OCR 全文から Claude が設問を構造化抽出（設問番号・設問文）
 → 各設問へ App 33 の記録（ヒアリング・起算点メモ・面談記録）を根拠に回答案を下書き
 → {{設問と回答}} に整形して docx 生成 → App 30 に起票（承認待ち）
 → ✅ 弁護士が全文確認・修正（法的判断 — 特に「知った日」「処分行為」への回答）
 → 依頼者署名が必要な書式の場合は M4 で依頼者へ郵送→署名→M5 受領 → 裁判所へ M4 承認発送
```

- Claude 下書きの禁則: 記録にない事実の創作禁止 / 記録と矛盾する回答禁止 /
  不明な設問は「【弁護士確認】」プレースホルダを残して人に委ねる
- 照会書の書式は裁判所ごとに異なるため、テンプレートは「表題・当事者表示・
  設問回答ブロック・署名欄」の汎用構成とし、設問部分は差込で吸収する

## 3. 上申書（3ヶ月超過時の事情説明・`houki/上申書_熟慮期間.docx`）

死亡から3ヶ月経過後の申述で、起算点が死亡日でないこと（債権者からの通知で初めて
相続を知った等）を説明する書面。**本ユニットで最も法的判断の濃い文書**。

| プレースホルダ | ソース |
|---|---|
| `{{事件の表示}} {{申述人_表示}} {{被相続人_表示}}` | App 33 |
| `{{時系列}}` | 死亡日・知った日・知った経緯から Claude が時系列箇条書きを下書き |
| `{{起算点の主張}}` | **起算点メモ（弁護士記入・03 §2）を主素材**に Claude が文章化 |
| `{{疎明資料目録}}` | 添付する資料（債権者通知の写し等 = M5 受領物）の目録 |

- 生成トリガー: 複雑性フラグ「死亡3ヶ月超過」かつ 起算点確定済=yes
  （熟慮期間超過警報（03 §4）からも生成をキューできる）
- **承認の二重化**: 通常の App 30 承認に加え、生成直後に弁護士へ
  「上申書下書きができました。内容の精読が必要です」と**専用文言**で通知する
  （定型書類と同じ温度感で流れ作業承認されるのを防ぐ）
- Claude 下書きの位置づけ: 時系列整理と文章化の補助。**主張構成の根拠は必ず
  起算点メモ（人の判断）から取り、AI が独自の法的主張を生成することを禁止**する

## 4. 期間伸長申立書（`houki/期間伸長申立書.docx`・03 §5 連動）

- 申立人・被相続人・伸長を求める理由（書類収集状況から自動整理）を差込
- 生成トリガー: 期間伸長申立=検討中 への変更（弁護士操作）→ 下書き生成 → App 30 承認発送
- 上申書と同じ「専用文言の承認通知」を使う

## 5. 完了報告書（`houki/完了報告書.docx`）

- 受理通知受領後に自動生成（受理年月日・事件番号・返却書類目録を差込）
- 原本返却の M4 送付案内（同封物ブロック: 戸籍原本一式 / 受理通知書写し / 完了報告書）
  と同時に App 30 起票 → 承認 → 発送

## 6. テスト観点（実装タスク完了条件用）

- 各テンプレートの全プレースホルダ差込（ゴールデンファイル比較）
- 生成前提条件のガード（起算点未確定で申述書生成 → エラー + 警報）
- 照会書: 設問抽出の構造化（サンプル照会書 OCR テキストでの回帰テスト）・
  「【弁護士確認】」残置の動作
- 上申書: 起算点メモ空欄なら生成拒否（AI 単独の主張構成を許さないガード）
