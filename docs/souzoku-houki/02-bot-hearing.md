# 02. Bot ヒアリング設計

相続放棄専用 LINE 公式アカウント（07 §3）でのヒアリング・複雑性フラグ判定・
チャネル選択・トリアージの設計。

## 1. ヒアリング方式：tool use による段階収集

時効援用の `SYSTEM_PROMPT`＋マーカー方式（`[KINTONE_RECORD]`）は温存しつつ、
相続放棄は **chat_responder と同じ tool use 方式**で実装する（構造化・検証可能・
マーカーの JSON パース事故がない）。

```
Claude tool: record_hearing
  input_schema:
    phase:        "1_deceased" | "2_dates" | "3_relation" | "4_assets" | "5_others" | "6_applicant"
    fields:       {収集済みフィールドの部分更新 dict}
    phase_done:   boolean（そのフェーズの必須項目が揃ったか）
    hearing_done: boolean（全フェーズ完了）
```

- 会話履歴は App 28 チャットログ（既存・line_user_id で分離）を流用
- `fields` は受信のたびに App 33 へ**逐次 upsert**（時効援用の「5項目揃ったら一括登録」と
  異なり、途中離脱してもデータが残る。既知の不具合#4「in-memory 消失」の影響を受けない）
- ヒアリング再開: App 33 に途中レコードがあれば「続きから」を Claude に指示

## 2. 質問項目（フェーズ順）

| フェーズ | 質問項目 | App 33 フィールド（04 参照） |
|---|---|---|
| 1. 被相続人 | 亡くなった方の氏名・依頼者との続柄 | 被相続人氏名 / 続柄 |
| | 最後の住所（市区町村まででも可）・本籍（分かれば） | 被相続人最後の住所 / 被相続人本籍 |
| 2. 日付（最重要） | **死亡日**（分からなければおおよそ） | 死亡日_申告 |
| | **死亡を知った日**・**自分が相続人だと知った日**（別々に質問） | 死亡を知った日_申告 / 相続人と知った日_申告 |
| | 知った経緯（役所からの通知・債権者からの請求・親族からの連絡 等） | 知った経緯 |
| 3. 相続順位 | 依頼者は配偶者・子・親・兄弟姉妹のどれか | 相続順位 |
| | 先順位者（子・親）の有無と、その人達が放棄したか | 先順位相続人の状況 |
| 4. 財産・負債 | 借金・督促の有無、督促状・訴状が届いているか | 負債概況 / 訴訟督促有無 |
| | 遺産（預貯金・不動産・車等）の有無、**使った・処分した・解約したものがないか** | 財産概況 / 財産処分有無 |
| 5. 他の相続人 | 同順位の相続人（兄弟等）の人数・一緒に放棄したい人がいるか | 他の相続人 / 同時申述希望 |
| 6. 依頼者本人 | 氏名・住所・生年月日・電話・メール、**依頼者本人が相続人か**（親族代理の相談か） | 顧客名 / 住所 / 生年月日 / 電話番号 / メールアドレス / 本人区分 |
| | 未成年・成年後見の関与有無 | 未成年後見関与 |

- 日付の聞き方: 「正確に」を求めず、曖昧なら `YYYY-MM 頃` を許容して `_申告` フィールドに
  そのまま記録。**確定は弁護士**（03 §2）
- フェーズ4の財産処分の質問文言は法定単純承認（民法921条）に直結するため、
  誘導にならない中立表現をテンプレート化しプロンプトに固定する

## 3. 複雑性フラグの判定ロジック

判定は**ルールベースを一次**とし、自由回答の解釈のみ Claude 補助（tool use の
`set_complexity_flags`）。フラグは App 33 の CHECK_BOX `複雑性フラグ` に保存する。

| フラグ | 一次判定ルール（機械的） | Claude 補助が要る場合 |
|---|---|---|
| 死亡3ヶ月超過 | `今日 - min(死亡日_申告, 死亡を知った日_申告) > 90日` ※安全側: 死亡日基準でまず判定 | 日付が「〜頃」の曖昧表現の解釈 |
| 先順位放棄が絡む | 相続順位 ≠ 配偶者・子 かつ 先順位相続人の状況に「放棄」を含む | 家族関係の自由記述の解釈 |
| 財産処分の可能性 | 財産処分有無 = あり/不明 | 「葬儀費用に使った」等のグレー記述の検出 |
| 訴訟・督促あり | 訴訟督促有無 = あり | 書類名の解釈（訴状/支払督促/催告書） |
| 依頼者が本人でない | 本人区分 ≠ 本人 | — |
| 未成年・後見関与 | 未成年後見関与 = あり | — |

- **判定閾値は安全側**: 曖昧・不明・矛盾は該当フラグを立てる（偽陰性を出さない）。
  フラグの解除は弁護士のみ（kintone 上で外す）
- フラグ確定時に `複雑性判定メモ`（判定根拠の1〜2文）を Claude が書き込む（弁護士向け）

## 4. チャネル選択の分岐

```
ヒアリング完了（hearing_done=true）
 ├─ フラグ 0 個 → 3択を提示（LINE クイックリプライ）
 │    A 来所面談 / B 電話またはZoom / C LINEのみで完結
 │    ├─ A or B → 予約枠提示へ（05）
 │    └─ C → 見積提示へ
 └─ フラグ 1 個以上 → C を提示しない（A / B の2択のみ）+ 引き上げ通知:
      「ご状況を確認したところ、期限や手続きの進め方について弁護士から直接
       ご説明した方が確実な点がございます。お電話またはZoom、もしくはご来所にて
       お話しさせていただけますでしょうか。（ご相談内容が複雑というだけで、
       ご依頼いただけないという意味ではございませんのでご安心ください）」
```

- 引き上げ通知は**定型文**（config で差し替え可能）。フラグの中身は依頼者に開示しない
  （「財産処分の疑いがあるため」等の表現は不安・防御反応を招く）
- 確定チャネルと引き上げ有無は App 33 に記録（`希望チャネル` / `確定チャネル` / `引き上げ理由`）
- **即時警報の例外**: 残日数 30 日未満（03 §4）を検知したら、チャネル分岐を待たず
  その時点で弁護士 LINE 警報（案件レコード No 付き）

## 5. トリアージ：相続放棄版カテゴリ定義

chat_responder のユニット対応版（07 §2）で使う。**時効援用との差分**は
「期限・財産処分に関わる質問は一般論でも承認必須に倒す」こと。

### 自動送信 OK（AUTO_SEND_CATEGORIES_HOUKI）

| カテゴリ | 備考 |
|---|---|
| 挨拶・雑談 | 既存と同じ |
| 手続きの一般的な流れ | 申述の一般的な流れの説明のみ。**期限に触れる回答は不可**とプロンプトで禁止 |
| 必要書類の案内 | 定型（戸籍・住民票・委任状） |
| 費用の定型案内 | 料金表の範囲 |
| 進捗の事実回答 | App 33 status の事実のみ（「裁判所に提出済みです」等） |
| 営業案内・アクセス | 事務所所在地は config（OFFICE_INFO）から差し込み（移転対応） |
| 予約の変更・確認 | 予約枠の事実操作（05 §4）。日程調整は機械的操作のため自動可 |

### 承認必須（弁護士確認）

| カテゴリ | 相続放棄固有の理由 |
|---|---|
| 法的判断・見通し | 既存と同じ |
| **熟慮期間・起算点** | 「あと何日ですか」「間に合いますか」も個別事案の法的判断。残日数の開示は弁護士承認後のみ |
| **財産処分・保存行為の可否** | 「預金をおろしていい？」「家を片付けていい？」＝法定単純承認リスク。誤答は致命的 |
| **他の相続人・順位繰上りの相談** | 利益相反の可能性検知を含む |
| 債権者対応 | 督促への対応指示は法的判断 |
| 費用交渉・減額相談 / クレーム・不満 / 解約・辞任関係 / 緊急対応 / 本人確認不能・第三者 / その他判断系 | 既存と同じ |

- システムプロンプトの禁則に追加: 「熟慮期間の残日数・間に合うかどうかの言及禁止」
  「財産の使用・処分・解約への許可/黙認と読める表現の禁止」
- 承認フロー自体は既存 App 29（承認キュー）をそのまま使う（レコードにユニット識別列を
  追加せず、`カテゴリ` と顧客名で判別可能。将来必要なら App 29 に `ユニット種別` を追加）

## 6. 異常系

| 事象 | 検知 | 対応 |
|---|---|---|
| Claude 全断 | 既存 ClaudeUnavailableError | 既存 handle_claude_outage と同じ（確認中定型文 + App 29 要対応 + 警報） |
| ヒアリング途中で残日数逼迫が判明 | 日付フィールド upsert 時 | 即時弁護士警報（03 §4） |
| 日付の矛盾（知った日 < 死亡日 等） | upsert 時のルール検証 | Bot が聞き直す。2回失敗で複雑性フラグ「日付不整合」+ 承認キュー |
| 依頼者が途中離脱 | 日次ジョブ（最終メッセージから 3 日） | リマインド1回 → さらに 7 日で「いつでもどうぞ」定型 → 以後放置（警報しない） |
