# 04. kintone 設計：相続放棄案件アプリ・予約枠アプリ

新設2アプリ（仮番号: ★App 33 相続放棄案件 / ★App 34 予約枠）。
App 21 の構造（LINEユーザーID・status・顧客情報 + Webhook/API トークン方式）を踏襲し、
UNIT_CONFIG のエントリ追加だけで発送/受領ハブに乗る。
作成直後に `EXPECTED_KINTONE_SCHEMA` へ登録し日次死活監視に乗せる（ハブ 02 §7 と同じ規約）。

## 1. ★App 33 相続放棄案件

### 1.1 基本・ルーティング（App 21 互換部分）

| フィールドコード | 型 | 選択肢 / 用途 |
|---|---|---|
| `LINEユーザーID` | SINGLE_LINE_TEXT | チャネル分離（07 §3）後も既存検索式を流用 |
| `status` | DROP_DOWN | 問い合わせ / ヒアリング完了 / 受任判断待ち / 見積提示 / 契約待ち / 決済待ち / 受任 / 書類収集中 / 申述書作成 / 裁判所提出済 / 照会書対応 / 受理 / 完了 / 不受任 / 辞任 |
| `顧客名` `住所` `生年月日` `電話番号` `メールアドレス` | SINGLE_LINE_TEXT | App 21 と同名（chat_responder 流用のため） |
| `本人区分` | DROP_DOWN | 本人 / 親族（本人依頼予定） / その他 |
| `本人確認書類` | FILE | 身分証明書の画像/コピー（チャネル別取得・01 [4a]） |
| `本人確認ステータス` | DROP_DOWN | 未 / 確認済 — **弁護士のみ**が確認済にする（申述パッケージ前提条件・09 §3.1） |
| `cloudsign_document_id` | SINGLE_LINE_TEXT | 既存 CloudSign Webhook の検索キー（07 §2） |
| `Stripe決済ID` / `入金状況` | SINGLE_LINE_TEXT / DROP_DOWN(未 / 入金済み) | 決済 Webhook 書き込み先 |

ルーティング分類（UNIT_CONFIG に登録・chat_responder 汎用化後に使用）:
- HEARING = {"", 問い合わせ} / POST_ENGAGEMENT = {受任, 書類収集中, 申述書作成, 裁判所提出済, 照会書対応, 受理, 完了} / それ以外 = PRE

### 1.4 チャネル・複雑性

|---|---|---|

| `確定チャネル` | DROP_DOWN | 同上（引き上げ後の値） |

| `受任判断` | DROP_DOWN | 未 / 受任可 / 不受任 — **弁護士のみ**。複雑性フラグ有り案件は「受任可」になるまで契約に進めない |
| `面談記録` | MULTI_LINE_TEXT | A/B 実施後に弁護士が記入 |

### 1.5 書類チェックリスト（SUBTABLE `書類チェック`）

書類収集の進捗管理と M1/M5 連携の中核。1行 = 収集すべき書類1点。

| 列フィールドコード | 型 | 用途 |
|---|---|---|
| `書類名` | DROP_DOWN | 被相続人死亡記載戸籍 / 被相続人住民票除票 / 申述人戸籍 / 委任状 / 収入印紙 / 切手 / その他 |
| `対象者` | SINGLE_LINE_TEXT | 誰の書類か |
| `取得方法` | DROP_DOWN | 依頼者郵送 / 職務上請求 / 事務所手配 |
| `書類状態` | DROP_DOWN | 未 / 依頼中 / 発送済 / 請求中 / 受領 / 不要（委任状行は 未(未発送)→発送済→受領 で遷移・01 [4a]） |
| `発送管理No` | SINGLE_LINE_TEXT | 職務上請求の App 30 レコード番号（M1 起票時に Railway が記入） |
| `同封対象` | CHECK_BOX(同封) | 申述パッケージの疎明資料として同封する行（09 §3.2。超過型は受領時に自動チェック） |

- 初期行は受任時に**続柄別の必要戸籍マトリクス（10 §2-3）**から Railway が自動生成
  （順位繰上りケースは自動導出を停止し弁護士が個別確定・10 §2）
- M5 の受領・返送消込時に `書類状態=受領` へ自動更新（案件紐付け経由・ハブ 08 §3）。
  連続戸籍の反復ループでは受領のたびに次請求の行が自動追加される（10 §4）
- 「未/依頼中/発送済/請求中 が残っている」ことが 03 §5 の伸長検知の入力になる

SUBTABLE 外の関連フィールド:

| フィールドコード | 型 | 用途 |
|---|---|---|
| `連続戸籍充足` | RADIO_BUTTON(no/yes) | 出生から死亡までの連続完成の宣言。**弁護士のみ**（10 §4。申述パッケージ前提条件の入力） |

## 2. ★App 34 予約枠（05 の実装対象）

1レコード = 1枠（30分/60分は config）。

| フィールドコード | 型 | 用途 |
|---|---|---|
| `枠開始日時` | DATETIME | |
| `枠種別` | DROP_DOWN | 来所 / 電話Zoom / 共用 |
| `枠状態` | DROP_DOWN | 空き / 仮押さえ / 確定 / 弁護士ブロック / 取消 |
| `仮押さえ期限` | DATETIME | 仮押さえから24h（超過で日次ジョブが自動解放） |
| `案件アプリID` / `案件レコードID` / `顧客名表示用` | SINGLE_LINE_TEXT | ハブと同じ案件参照3点（ユニット非依存・将来他ユニットも同じアプリを使う） |
| `実施方法メモ` | MULTI_LINE_TEXT | Zoom URL・来所案内（確定時に Railway が記入） |

- 枠の生成: 週次ジョブが config の営業ルール（曜日・時間帯・週あたり上限）から
  **2〜4週間先の枠を自動生成**。弁護士は塞ぎたい枠を `弁護士ブロック` にするだけ
  （平常時人間ゼロ: 枠登録作業を発生させない）
- ダブルブッキング防止: `枠状態=空き` の revision 指定更新（hub/kintone の楽観ロック）で
  仮押さえを claim。競合したら Bot は次の候補を提示

## 3. UNIT_CONFIG 登録内容（ハブ 03 §10 のエントリ追加）

### 3.1 正式料金（2026-07-03 弁護士確定・WordPress 料金ページ掲載値・すべて税込）

| 区分 | 1人目 | 同一被相続人の2人目以降 |
|---|---|---|
| 標準型（死亡から3ヶ月以内） | **77,000円** | 1人 33,000円 |
| 3ヶ月超過型 | **88,000円〜**（事案により上振れあり・**見積り段階で確定**） | 1人 33,000円 |
| 期間伸長手続き | **110,000円** | 1人 33,000円 |

- **債権者対応**: 3社まで無料。4社目以降 **1社 3,000円**（書面送付＋簡単な電話連絡2回程度。
  交渉が必要な場合は別途見積り）
- **実費**: 1人あたり **10,000円 定額**（通信費・予納郵券・戸籍取得費用込み）
- Bot の費用固定文・LP・広告はこの表と**一字一句一致**させる運用とする
  （超過型の「〜」の性質上、Bot は「88,000円〜・正式なお見積りでご案内」の形で案内し、
  確定額の提示は見積り段階＝弁護士確認を経る）

```python
UNIT_CONFIG["相続放棄"] = {
    "case_app_env": ("APP_HOUKI", "TOKEN_HOUKI"),
    "customer_name_field": "顧客名",
    "customer_addr_field": "住所",
    "channels": ["職務上請求", "送付案内", "スキャン受領"],   # e内容証明・FAX は当面使わない
    "template_dir": "houki",
    "return_deadline_days": 21,
    # ── 料金（§3.1 の正式値・2026-07-03 弁護士確定・税込）──
    "fees": {
        "標準型":       {"1人目": 77_000, "2人目以降": 33_000},
        "3ヶ月超過型":  {"1人目": 88_000, "2人目以降": 33_000,
                         "備考": "88,000円〜。事案により上振れあり・見積り段階で確定"},
        "期間伸長手続き": {"1人目": 110_000, "2人目以降": 33_000},
    },
    "creditor_notice": {                             # 債権者対応（§3.1）
        "included": 3,                               # 3社まで無料
        "additional_per_creditor": 3_000,            # 4社目以降・1社（書面送付+電話2回程度）
        # 交渉が必要な場合は別途見積り（自動計算しない・弁護士判断）
    },
    "jippi_per_person": 10_000,                      # 実費定額/人（通信費・予納郵券・戸籍取得費込み）
    "mail_roundtrip_days": 7,                        # C チャネルの委任状郵送往復（03 §5・10 §5）
    "collection_days": {"子": 14, "直系尊属": 28,     # 続柄別の収集見込み日数（初期値・実測で更新）
                        "兄弟姉妹": 42, "甥姪（代襲）": 56},
    "hearing_statuses": {"", "問い合わせ"},
    "post_engagement_statuses": {"受任", "書類収集中", "申述書作成",
                                 "裁判所提出済", "照会書対応", "受理", "完了"},
    "line_channel_env": ("HOUKI_LINE_CHANNEL_SECRET", "HOUKI_LINE_CHANNEL_ACCESS_TOKEN"),
}
```

- ハブ側（App 30・M1/M4/M5・同封物マスタ）への追加作業は
  「`ユニット種別` 選択肢に `相続放棄` を追加 + App 32 に相続放棄用ブロック行を追加 +
  `docx_templates/houki/` 配置」のみ（ハブ設計 01 §5.3 の拡張ポイントどおり。
  コード変更が必要になった箇所は 07 §2 の一般化タスクとして扱う）

## 5. OFFICE_INFO（config・移転対応）

事務所所在地・アクセス・Zoom URL 等は**全テンプレート・Bot 文言から config 参照**とし、
移転時は config 1箇所の変更で完結させる:

```python
OFFICE_INFO = {
    "名称": "大野法律事務所", "郵便番号": "...", "住所": "埼玉県川口市...",
    "電話": "...", "FAX": "...", "アクセス案内": "...", "Zoom固定URL": "...",
    "管轄裁判所_初期値": "さいたま家庭裁判所",
}
```

（既存の M1/M4 で設計済みの「事務所固定情報」と同一の定数を共用する）
