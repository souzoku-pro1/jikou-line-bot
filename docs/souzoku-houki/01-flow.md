# 01. 全体フロー：LINE 友だち追加から完了報告まで

> 本ファイルと記述が衝突する場合は正本が優先する（受任フロー=B案ベース・裁量スキップ、

各ステップの「自動（Bot/Railway）」「人間（弁護士/事務員/依頼者）」の分担を明示する。
記号: 🤖=完全自動 / ✅=弁護士承認（kintone 上の1操作） / 👤=人の実作業 / ⚠=異常時のみ LINE 警報

```
[0] LINE 友だち追加（相続放棄専用 LINE 公式アカウント。07 §3 参照）
 🤖 挨拶＋ヒアリング開始（02 §1）
      │
[1] Bot ヒアリング（02）
 🤖 段階収集: 依頼者情報 → 被相続人情報 → 死亡日・知った日 → 相続順位 →
    財産・負債の概況 → 他の相続人 → App 33 に記録（status=問い合わせ→ヒアリング完了）
 🤖 複雑性フラグ判定（ルール + Claude 補助・02 §3）
 ⚠ 熟慮期間の残りが少ない（30日未満）と判明した時点で即時弁護士警報（03 §4）
      │
[2] チャネル選択（02 §4）
 🤖 ヒアリング完了時に案件類型（標準型/3ヶ月超過型）を死亡日ベースで自動判定（02 §3a）
 🤖 フラグなし かつ 標準型 → A/B/C を依頼者が選択
 🤖 フラグあり または 3ヶ月超過型 → C を提示せず B 以上に自動引き上げ + 定型の丁寧な通知
 🤖 A/B 選択時 → 予約枠提示・仮押さえ（05）。C 選択時 → そのまま [3] へ
    ※ C は「面談なし」の意味であり完全非対面ではない（委任状の郵送1往復あり・[4a]）。
      選択時に往復日数込みの見込みを定型文で案内
      │
[3] 見積・受任判断
 🤖 類型別料金（UNIT_CONFIG `fees`・02 §3a）から見積を自動提示
    + 続柄別の必要戸籍の種類・概算通数を自動案内（10 §3）
 ✅ 受任可否は弁護士承認: 複雑性フラグ付き案件・3ヶ月超過案件は
    「受任判断待ち」として承認キューに入り、弁護士が面談/記録確認後に承認
    （法的判断は必ず弁護士 — 制約の実装点①）
 👤 A/B チャネルは面談・電話/Zoom を実施（予約枠どおり）。実施後、弁護士が受任可を kintone で確定
      │
[4] 契約・決済（時効援用と同型・電子で統一）
 🤖 CloudSign で委任契約書送付（電子締結）・Stripe 決済リンク送付
    （既存 cloudsign_webhook / /webhook/stripe の一般化・07 §2）
 🤖 **受任確定トリガー = CloudSign 締結 + Stripe 決済完了の両方**が揃った時点で
    status=受任 とし、受任時フック（[4a] 委任状発送・[5] 除票請求・チェックリスト初期化）を発火
 ⚠ 締結・決済が N 日滞留 → リマインド自動送信 → さらに滞留で弁護士警報
      │
[4a] 受任時取得書類（依頼者から取得する3点。裁判所提出用の戸籍類とは区別）
 🤖 委任契約書 …… CloudSign 電子締結（[4]。締結+決済完了=受任確定） — 電子のまま
 🤖 手続委任状 …… **必ず紙**（家裁提出のため署名押印必須）。受任確定と同時に
    M4 送付案内で「委任状＋記入例＋返信用封筒」の発送を自動起票
    → ✅ 承認 → 👤 発送 → 依頼者が署名押印・返送 → M5 受領で消込
    （書類チェックの委任状行: 未発送 → 発送済 → 受領・04 §1.5）
 🤖 身分証明書 …… チャネル別に取得方式を分岐:
    C=LINE 画像アップロード / A=対面確認＋コピー / B=LINE 画像または委任状返送に同封
    → App 33 に添付（`本人確認書類`）→ ✅ 弁護士が本人確認チェック（`本人確認ステータス=確認済`。
    申述パッケージ前提条件ゲートの1条件・09 §3.1）
      │
[5] 書類収集（熟慮期間タイマー稼働中・03 の監視対象）
 🤖 **受任確定と同時に被相続人の住民票除票（附票）の M1 職務上請求を自動起票**
    （管轄家裁確定の前提のため最優先・10 §1。取得遅延14日で警報）
 🤖 依頼者へ必要書類の案内（必要戸籍の種類・概算通数は 10 §3 の導出結果を使用）
 👤 依頼者が委任状等を郵送 → 事務所到着
 🤖 M5 スキャン受領: 受信箱 PDF → OCR → 分類 → App 33 案件へ自動紐付け・チェックリスト消込
 🤖 戸籍等の職務上請求: 連続戸籍は「取得→読解→✅ 承認→次請求の自動起票」の反復ループ
    （10 §4）。各請求はハブ M1 のフローそのまま（✅ 承認 → 👤 印刷・投函 → M5 返送消込）
 ⚠ 書類チェックリストが残日数閾値までに揃わない → 警報 + 期間伸長申立ての要否検知（03 §5）
      │
[6] 申述書作成（06）
 🤖 App 33 のデータから相続放棄申述書 docx を自動生成（hub/docx_builder + houki テンプレート）
 🤖 3ヶ月超過案件は上申書（事情説明）の下書きを Claude が生成
 ✅ 弁護士が内容を確認・修正（上申書は法的判断のため必ず精読 — 制約の実装点②）
      │
[7] 裁判所提出（発送/受領ハブ M4 送付案内チャネル）
 🤖 App 30 に「送付案内（裁判所宛）」を自動起票: 申述書＋戸籍等一式＋収入印紙・
    切手のチェックリスト＋宛名ラベル（管轄家裁）を prepare が生成
 ✅ 弁護士が発送管理レコードで承認（対外発信の承認 — 制約の実装点③）
 👤 事務員が印刷・印紙貼付・投函 → 発送済 → 返送待ち（照会書・受理通知を待つ）
      │
[8] 照会書対応
 🤖 M5 が裁判所からの照会書を受領・分類（doc_type=裁判所書類）→ App 33 に紐付け
    → status=照会書対応 に自動遷移 + 依頼者へ「裁判所から照会書が届きました」定型連絡
 🤖 照会書の設問を OCR から抽出し、ヒアリング済みデータで回答案 docx を Claude が下書き
 ✅ 弁護士が回答案を確認・修正（法的判断）
 👤 依頼者の署名が必要な場合: M4 で依頼者へ郵送 → 署名返送 → M5 受領
 ✅→👤 裁判所への返送も [7] と同じ M4 承認発送
      │
[9] 受理
 🤖 M5 が相続放棄申述受理通知書を受領・分類 → App 33 status=受理 + 依頼者へ受理報告 LINE
 🤖 受理証明書の取得要否を依頼者に確認（債権者対応が必要な場合）
      │
[10] 完了報告・書類返却
 🤖 完了報告書 docx 生成 + 原本一式の返却を M4 送付案内で起票（同封物マスタに
    「戸籍原本一式」「受理通知書写し」ブロックを追加するだけ）
 ✅ 承認 → 👤 発送 → 🤖 App 33 status=完了
 🤖 （任意）債権者への受理通知の送付が受任範囲なら、M3 FAX / M4 郵送で同様に処理
```

## 人間が登場する場面の一覧（それ以外は全自動）

| 場面 | 誰 | 操作 |
|---|---|---|
| 受任可否・起算点確定・上申書/回答案の承認 | 弁護士 | kintone で確認・ステータス変更 |
| 面談・電話/Zoom の実施 | 弁護士 | 予約枠どおり実施し、結果を1フィールド記入 |
| 発送管理（App 30）の承認 | 弁護士 | ハブ共通の承認操作 |
| 印刷・印紙・投函・追跡番号入力 | 事務員 | ハブ M1/M4 と同一（物理制約） |
| 警報対応 | 弁護士 | LINE 警報を受けて kintone を開く |

## 時効援用フローとの構造差分

| 観点 | 時効援用（既存） | 相続放棄（本設計） |
|---|---|---|
| 期限管理 | なし | **熟慮期間3ヶ月**が全フローを貫く（03） |
| 受任チャネル | LINE 完結のみ | A 来所 / B 電話・Zoom / C LINE 完結の三段構え + 自動引き上げ |
| 対外提出先 | 債権者（内容証明・FAX） | **家庭裁判所**（郵送・照会書の往復あり） |
| 書類収集 | ほぼなし | 戸籍等の収集が主工程（M1/M5 をフル活用） |
| 受任判断 | 定型（時効期間の形式判定） | 複雑性フラグにより**弁護士判断必須**の場合あり |
