## 2. 作成後の手順（1アプリごとに実施。App 30/31/32 のときと同じ流儀）

1. 【人】完了報告の URL（`https://～.cybozu.com/k/NN/`）で**実番号を確定**
2. 【人】アプリの 設定 → カスタマイズ/サービス連携 → **APIトークン** を生成し、
   アクセス権 **「レコード閲覧」「レコード追加」「レコード編集」** に✅ →
   保存 → **右上の「アプリを更新」を必ず押す**（押し忘れると GAIA_IA02 になる・既往2回）
3. 【人】Railway に登録（値は実物に置き換え）:
   ```
   railway variables --set "APP_KOSEKI_BOOK=33" --set "TOKEN_KOSEKI_BOOK=<トークン>"
   ```
   （5アプリまとめて1コマンドでもよい。--set を並べる）
4. 【Claude/Sonnet】`EXPECTED_KINTONE_SCHEMA`（config.py）に追加 → 日次死活監視の対象化
   （「作成直後に登録」が既存規約。ギャップ#7 の再発防止）
5. 【Claude/Sonnet】form/fields.json による**機械突合**（指示書のフィールドコード・
   型・選択肢と実機の完全一致を検証。App 30 検収と同じ方式。不一致は preview API で修正）

## 3. 指示書共通の注意（cu-app30 と同じ原則）

- フィールドコードは**日本語**・「ステータス」という語は kintone 予約語のため
  フィールドコードに使わない（本5アプリでは該当フィールドなし。「読解状態」は可）
- 選択肢・フィールドコードは**コピペ**（手入力の全角/半角ゆれがプログラムを止める）
- 日付フィールドは**「レコード登録時の日付を初期値にする」のチェックを外す**
  （App 30 作成時に defaultNow で修正作業が発生した既往）
- 指示書にないフィールド・ラベル・罫線を置かない。1指示書=1アプリ。迷ったら停止して報告
