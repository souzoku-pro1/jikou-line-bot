### 1.2 応答方針（プロンプト構造・_SYSTEM_PROMPT_BASE :272-）

「会話スタイル（最重要）」節に**既に人間っぽさの指示が存在する**（逐語）:

> - 自然な会話を最優先。テンプレートの棒読み感を出さない
> - 同じことを二度言わない。…既に確認済みの質問・確認事項は絶対に繰り返さない
> - 1メッセージは短く。…詳細は聞かれたら答える
> - 顧客への質問は一度に1つ、答えやすい形で聞く
> - 敬体（です・ます調）、1メッセージ400字以内を目安とする

### 1.3 品質に影響する構造上の特徴（観察）

- 定型文面が多層にある: 即時定型（PENDING_REPLY・CRISIS_SUPPORT_REPLY 等 :66-106）・
  FAQ定型・必須文言（FEE_REQUIRED_PHRASES・留保文言 B型 :192-）。**定型と生成文の
  接続部が「棒読み感」の主要リスク**（必須文言の挿入が文脈から浮く構造)。
- サーバーガードは**降格のみ**（品質を上げる方向の介入はない）。降格時の顧客体験は
  PENDING_REPLY（確認中）固定＝**待たされ感**の発生点。
- 履歴は直近10往復固定。長い相談での「前に言ったことを忘れる」体験の構造的上限。

## 3. 相1: ログ非依存の改善設計（先行可）

### 3.1 現行プロンプト構造の改善設計（対象3点）

1. **必須文言の接続部**: 費用注意書き・留保文言（B型）等の必須ブロックが本文と
   無接続に並置される構造を、「直前の顧客発話を受ける一文 → 必須文言 → 次の行動の
   一文」の**三段接続の型**に改める（必須文言そのものは一字も変えない＝v2.4 の
   安全確定を維持。変えるのは前後の書き方の指示のみ）。
2. **降格時文言の再設計案**: 承認制降格時の ack が PENDING_REPLY 一種で固定される
   構造を、**カテゴリ群別の ack 3〜4 種**（法的判断系=「先生に確認して◯◯までに
   お返事します」型／費用交渉系／クレーム系）へ多様化する案。期限を述べる場合の
   運用整合（実際の承認所要時間）は[人]確認事項。
3. **共感の先出し**: 不安・焦りの表明を検知した場合「受け止めの一文を手続き説明の
   前に置く」ことをプロンプトの会話スタイル節へ明示追加する案（現行は「自然な会話
   最優先」の一般指示のみで個別規定なし）。

### 3.2 チャッピー型評価の適用（合成会話例での事前評価）

- **合成会話例**: PC-A が典型シナリオから合成したスレッド 20〜30 本
  （不安表明/費用質問/督促パニック/雑談/長期無応答後の再開等・**顧客データ由来の
  情報を一切含まない**・repo 管理可能でレビュー可能）。
- 評価軸（7本・スレッド単位 1-5 採点）:

| 軸 | 定義 | 測り方 |
|---|---|---|
| 共感の先出し | 不安の表明に、手続き説明の**前に**受け止めの一文があるか | 判定型（LLM judge＋人抜き取り） |
| 文長の適正 | 長さが問いの重さに釣り合うか | 実測＋判定型 |
| 質問数の規律 | 一度に1問・答えやすい形か | 機械計数＋判定型 |
| 専門用語密度 | 法律用語の裸出現頻度 | 用語リスト機械計数 |
| 不安への応答速度 | 不安表明→降格 ack 固定文の率 | 機械計数 |
| 反復回避 | 既確認事項の再質問・同一定型再送 | 判定型＋機械検出 |
| 棒読み感 | 必須文言・定型の接続が浮いていないか | 判定型 |

- **judge の校正を相1 で完了させる**: 別系統 LLM を審査員とし、軸定義＋1-5 の
  係留例を与える。合成会話に対する judge 採点と[人]（弁護士）採点の一致率を測り、
  係留例を調整してから相2 に入る（審査員のモデル選定・費用は[人]確認）。
- 相1 の検証形: 現行プロンプト vs §3.1 改訂案で**合成スレッドへの応答を再生成→
  盲検比較**（顧客影響ゼロ・オフラインのみ）。

### 3.3 相1 の顧客影響ゲート

- §3.1 の改善はいずれも**顧客に届く文言に影響**するため、実装票では

- 必須文言（費用・留保・禁止語）の削除・緩和は本トラックでは提案しない。
