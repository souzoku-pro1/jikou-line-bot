## 3. 判別方法の実地検討（住民票（現在）vs 除票 vs 附票）

読解（OCR テキスト）での判別材料:

| 書類 | 判別材料（記載実態） | 誤読リスク |
|---|---|---|
| 住民票の除票 | 表題「住民票**の除票**」または「除票」表記／**消除事由・消除日**（転出・死亡等）の記載／「除票につき〜」注記 | 表題が「住民票」のまま除票欄だけで示す自治体書式がある（表題のみ判定は不可） |
| 戸籍の附票 | 表題「**戸籍の附票**」（本籍・筆頭者＋住所履歴の構成） | 「附票の写し（除附票）」の亜種あり |
| 住民票（現在） | 表題「住民票」＋消除記載なし | 消除記載の見落とし＝除票を現在住民票と誤読 |

- 設計方針: tool スキーマに `resident_doc_kind`（enum: 住民票 / 住民票の除票 /
  戸籍の附票 / 不明）＋フィールド別 confidence を持たせる（R3/S6 と同一規約）。
- **判定条件は書類種別ごとに分離する（fix1・VOCAB-03 で「二材料の合致」の
  一律規則を撤回・種別別へ精密化）**:
  - **住民票の除票** = **消除系記載（消除事由・消除日・「除票につき」注記の
    いずれか）の実在を必須条件**とする（表題のみでは除票と判定しない）。
  - **戸籍の附票** = **表題（「戸籍の附票」）＋構造（本籍・筆頭者＋住所履歴の
    構成）**の両方。
  - **住民票（現在）** = 表題「住民票」＋**消除系記載が無い**こと。
  - **材料が競合**（例: 表題は附票だが消除系記載あり・表題と構造の不一致）は
    **「不明」**へ倒す（どれか一つに寄せない）。
- **判別不能（不明・低確信度・材料競合）は充足に数えない**（R5）。除票と現在
  住民票の誤読は「除票取得済みと誤認→請求候補から外す＝過少提案（危険側）」に
  直結するための安全側規律。

## 4. 回送ゲート変更の影響範囲（実査）

- 変更点は `_FORWARD_LINES` への 1 entry 追加のみだが、下流は koseki lane
  （`ingest_koseki_pdf` → App33 起票 → koseki_reader）を**戸籍以外の書類が
  初めて流れる**ことになる:
  - koseki_reader のプロンプト（正本 02 §3・config KOSEKI_READER_PROMPTS）は
    戸籍前提＝**除票/附票用のプロンプト分岐 or 統合プロンプトの改定**が必要
    （02 §3 の改定範囲: 戸籍種別 enum・読解 JSON スキーマへの resident 系
    キー追加・確信度規約は既存踏襲）。
  - 人物化（koseki_person_sync）・連続性判定（koseki_chain）は**戸籍のみを
    対象とする現行維持**（除票/附票の読解行は対象外にする除外条件を追加＝
    誤って人物レコードを生成しない）。
  - 既存 pin（test_sortation_ingest.py:444「住民票・戸籍附票は回送しない」）は
    **意図的拡張として更新**（挙動変更を票で明示・回帰は新 pin で固定）。
- ゲート条件（auto 確定・confidence 閾値・SORTATION_FORWARD_ENABLED）は不変。

## 6. SHOKUMU-PLAN スタブ実装化の条件（R4・FB1 再発行の受け入れ条件）

- **【fix1・VOCAB-01 改定】充足判定は「種別の存在」ではなく候補行との相関一致で
  行う**（初版の「戸籍種別 in (…) の読解行が存在する」の単独条件を撤回——
  存在だけでは別対象者・別自治体の書類でも充足になる穴があった）。照合軸:
  1. **request_type 対応**: 候補行 `joh_removed` ↔ 読解種別「住民票の除票」・
     `fuhyo` ↔「戸籍の附票」（1:1・交差は充足にしない）。
  2. **対象 person**: 読解行の対象者が候補行の対象 person（被相続人）と一致
     （照合材料と一致判定の方式は裁定⑦——氏名照合は使わない既存規律との整合）。
  3. **自治体**: 読解行の交付自治体/住所地が候補行の `municipality` と一致
     （切り出しは §2A.1 規則を共用）。
  4. **様式 locus**: 候補行の様式（様式2）と書類の対応が崩れていないこと。
  5. **App33 行の有効状態・確認状態**: 読解状態が有効（要再読解・無効化行は
     除外）＋確認状態の要否は裁定④と統合。
  - **一致不能・多義（複数行が部分一致・照合材料欠落）は非充足**（R5 と同じ
    安全側＝過剰提案側へ倒す）。
- **【fix1・VOCAB-04】自動充足は confidence 単独で決めない**——裁定④の確信度
  条件は上記相関一致の**全軸成立と組み合わせて**のみ充足とする（confidence が
  高くても相関不成立なら非充足・相関成立でも confidence 不足なら非充足）。
- 本票 R1〜R3 の merge・実機 CU 完了が実装化の前提（FB1 再発行票で実装）。
