## 3. 判別方法の実地検討（住民票（現在）vs 除票 vs 附票）

読解（OCR テキスト）での判別材料:

| 書類 | 判別材料（記載実態） | 誤読リスク |
|---|---|---|
| 住民票の除票 | 表題「住民票**の除票**」または「除票」表記／**消除事由・消除日**（転出・死亡等）の記載／「除票につき〜」注記 | 表題が「住民票」のまま除票欄だけで示す自治体書式がある（表題のみ判定は不可） |
| 戸籍の附票 | 表題「**戸籍の附票**」（本籍・筆頭者＋住所履歴の構成） | 「附票の写し（除附票）」の亜種あり |
| 住民票（現在） | 表題「住民票」＋消除記載なし | 消除記載の見落とし＝除票を現在住民票と誤読 |

- 設計方針: tool スキーマに `resident_doc_kind`（enum: 住民票 / 住民票の除票 /
  戸籍の附票 / 不明）＋フィールド別 confidence を持たせる（R3/S6 と同一規約）。
- **判定条件は書類種別ごとに分離する（fix1・VOCAB-03 で「二材料の合致」の
  一律規則を撤回・種別別へ精密化）**:
  - **住民票の除票** = **消除系記載（消除事由・消除日・「除票につき」注記の
    いずれか）の実在を必須条件**とする（表題のみでは除票と判定しない）。
  - **戸籍の附票** = **表題（「戸籍の附票」）＋構造（本籍・筆頭者＋住所履歴の
    構成）**の両方。
  - **住民票（現在）** = 表題「住民票」＋**消除系記載が無い**こと。
  - **材料が競合**（例: 表題と構造の不一致）は**「不明」**へ倒す（どれか一つに
    寄せない）。
  - **【fix2・VOCAB-06 裁定＝充足可能】除附票（除かれた戸籍の附票）**:
    **附票表題（「戸籍の附票」・「附票の写し」「除附票」等の亜種含む）＋附票構造**
    が成立していれば、**消除系記載があっても材料競合としない**——`fuhyo` として
    充足可能。除票判定の「消除系必須」は**住民票系にのみ適用される独立の規則**で
    あり、附票系の消除系記載（除附票の消除日等）は附票判定を毀損しない。
    判定表（fix1 の種別別条件）へこの独立性を明記:

    | 種別 | 必須材料 | 消除系記載の扱い |
    |---|---|---|
    | 住民票の除票 | 消除系記載（必須） | 判定の必須材料 |
    | 戸籍の附票（除附票含む） | 附票表題（亜種含む）＋附票構造 | **競合としない**（除附票で自然に present） |
    | 住民票（現在） | 表題＋消除系記載なし | あれば除票側へ |
- **判別不能（不明・材料競合）は充足に数えない**（R5）。除票と現在住民票の誤読は
  「除票取得済みと誤認→請求候補から外す＝過少提案（危険側）」に直結するための
  安全側規律。~~低確信度~~ **【fix6・VOCAB-07 で整理】confidence は充足/非充足の
  判定材料から外す**（§6 の一意化どおり——confidence の役割は人手確認の優先度
  付け・再確認の材料に限る。判定は種別判定材料と §6 の相関＋人手確認済みで行う）。

## 4. 回送ゲート変更の影響範囲（実査）

  （`ingest_koseki_pdf` → App33 起票 → koseki_reader）を**戸籍以外の書類が

    対象とする現行維持**（除票/附票の読解行は対象外にする除外条件を追加＝
    誤って人物レコードを生成しない）。

    **意図的拡張として更新**（挙動変更を票で明示・回帰は新 pin で固定）。

     （無効化行等）は非充足**。

       請求先ではないため——誤って履歴中の一致で充足にしない）。
     - 切り出しは §2A.1 規則を共用。**不一致・複数解釈は非充足**。
  4. **様式 locus**: 候補行の様式（様式2）と書類の対応が崩れていないこと。
  5. **App33 行の有効状態・確認状態**: 読解状態が有効（要再読解・無効化行は
     除外）＋確認状態の要否は裁定④と統合。
  - **一致不能・多義（複数行が部分一致・照合材料欠落）は非充足**（R5 と同じ
    安全側＝過剰提案側へ倒す）。
