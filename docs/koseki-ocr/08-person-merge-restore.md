# 名寄せ統合の人手復元手順（監査JSONからの敗者レコード復元）

対象: R4-2b の名寄せ統合で物理削除された App 34（人物）レコードを元に戻したいとき。
第1版に取消語彙は無い（2026-07-07 裁定: 監査JSONによる人手復元まで）。

## 監査JSONの所在

統合1件につき1ファイル。App 30（発送管理）の当該封筒（件名「人物の名寄せ候補: …」・
発送ステータス=完了）の **成果物** に
`名寄せ統合監査_<勝者ID>-<敗者ID>.json` として添付されている。

内容（欠落なし・ラウンドトリップテストで固定済み）:

| キー | 内容 |
|---|---|
| `敗者レコード` | 削除前の敗者レコード全体（全フィールド＋サブテーブル全行・kintone GET 形そのまま） |
| `統合先レコードID` | 勝者（統合先）のレコード番号 |
| `削除レコードID` | 削除された敗者のレコード番号（復元後は**新しい番号になる**） |
| `統合日時` / `成立シグナル` / `ペアキー` | 監査情報 |
| `参照付け替え` | 削除前に 父/母/養父/養母人物ID を勝者へ付け替えた人物レコードの一覧 |
| `封筒レコードID` | 操作経路（この封筒自身） |

## 復元手順

1. **監査JSONの取得**: 封筒の成果物から該当 JSON をダウンロードする。
2. **敗者レコードの再作成**: `person_merge_exec.restore_payload_from_audit` が
   監査JSON→登録payload の変換（システムフィールド除去・サブテーブル全行の復元）を行う。

   ```python
   # Railway ssh または env の揃ったローカルで実行（PC-A は本番書き込み裁定が必要）
   import asyncio, json
   from hub import kintone
   from person_merge_exec import APP_KOSEKI_PERSON, restore_payload_from_audit

   audit = json.load(open("名寄せ統合監査_6-9.json", encoding="utf-8"))
   payload = restore_payload_from_audit(audit)
   new_id = asyncio.run(kintone.create_record(APP_KOSEKI_PERSON, payload))
   print("復元レコード No.", new_id)
   ```

3. **親エッジの戻し（必要な場合のみ）**: 監査JSONの `参照付け替え` に載っている
   人物レコードは、統合時に 父/母/養父/養母人物ID が勝者へ書き換えられている。
   統合自体を取り消すなら、該当レコードの当該フィールドを**復元後の新レコード番号**
   （旧敗者番号ではない）へ手で戻す。
4. **勝者側の手当て**: 統合で勝者に転記された値（勝者が空だったフィールド・
   サブテーブルの和集合行）は自動では戻らない。監査JSONの `敗者レコード` と
   見比べて、不要なら kintone 上で手で除去する。勝者の 名寄せ確定=確定 も
   必要に応じて戻す。
5. **再起票の抑止解除（統合をやり直す場合）**: スコアラーはペアキーの封筒が
   存在する限り同ペアを再起票しない（恒久抑止）。再検出させたいときは
   当該封筒のチャネル固有データからペアキー文字列を変更するか封筒を削除する
   （通常は不要）。

## 注意

- 復元レコードのレコード番号は元と変わる。名寄せキー・登場戸籍等の内容は
  監査JSONどおり完全復元される（作成者・作成日時等のシステム項目は新値）。
- 本手順の kintone 書き込みは本番操作。実行は裁定（指示の明示）を経ること。
