# 04. 相続人確定ロジック

確認済の人物グラフ（App 43）から法定相続人と法定相続分を**機械導出**する。
ただし**最終確定は弁護士**（souzoku-houki 10 の「連続戸籍充足=yes は弁護士のみ」と同じ原則）。
複雑ケースは自動確定せずフラグで弁護士判断に回す。

## 1. 導出の前提条件（満たさない場合は導出しない・警報）

1. 被相続人の `生死=死亡`・死亡日確定
2. 被相続人の出生から死亡までの戸籍が**連続している見込み**（01 §4 の機械判定。
   参考表示であり、導出結果の表示にも「連続戸籍は弁護士確認前」を明記）
3. 対象人物の `名寄せ確定=yes`（未確定の統合候補が残っていれば導出を保留）

## 2. 基本導出（機械が確定的に扱える範囲）

```
配偶者: 被相続人の身分事項に婚姻があり、死亡日時点で離婚・配偶者死亡がない者 → 常に相続人
第1順位（子）: 父/母ID が被相続人の実子＋養子。死亡日時点で存命の子
第2順位（直系尊属）: 子が1人もいない場合。父母（存命）→ 祖父母
第3順位（兄弟姉妹）: 第1・第2順位がいない場合。父母の子（半血は §3 フラグ）
法定相続分: 民法900条の基本分数（配偶者1/2×子等）。分数演算で厳密に（浮動小数不使用）
```

- 判定基準日は**死亡日**（存命判定・年齢計算とも）
- `生死=不明` の者が順位判定に影響する位置にいる場合 → 導出を保留し「要調査」警報
  （死亡記載がない＝存命、とは推定しない。02 §2 の原則）

## 3. 複雑ケースのフラグ（自動確定せず弁護士判断に回す）

| フラグ | 検知条件 | 機械の動作 |
|---|---|---|
| 代襲相続 | 子（または兄弟姉妹）が被相続人より先に死亡し、その者に子がいる | 代襲候補を**表示するが相続分は仮計算**（要確認マーク付き） |
| 数次相続 | 相続人が被相続人の**後に**死亡 | その相続人の相続人の調査が必要 → 導出を分岐せず警報（別案件化の提案） |
| 順位繰上り（放棄） | App 33（相続放棄案件）等から放棄情報がある・依頼者申告がある | 放棄を織り込んだ導出は**しない**（受理証明書の確認が前提・弁護士判断） |
| 半血兄弟姉妹 | 第3順位で父母の一方のみ共通 | 相続分1/2の仮計算＋フラグ |
| 養子と実子の併存・特別養子 | 養親子エッジあり | 普通養子は実親側にも相続資格が残る旨を表示・特別養子の判別は記載から不確実なためフラグ |
| 認知・非嫡出子 | 身分事項に認知 | フラグ（現行法は同等分だが記載の解釈は弁護士） |
| 胎児・行方不明・失踪宣告 | 記載・申告から検知 | フラグ・導出保留 |
| 再転相続・相続分譲渡 | 申告ベース | フラグ |

- フラグが1つでもあれば導出結果の表示は「**参考値（弁護士確認必須）**」の帯を付け、
  App 37 への反映（§4）をブロックする（弁護士がフラグを個別に解決してから反映）

## 4. 確定と下流への反映

```
機械導出（相続人候補リスト＋法定相続分の分数） → 弁護士がレビュー
 → 弁護士の確定操作（App 43 の相続資格を確定・案件の 連続戸籍充足=yes）
 → App 37（相続人・souzoku-shorui）へ自動起票: 氏名・続柄・法定相続分・
   データ源=戸籍読解・戸籍確認済=no（**App 37 側の 戸籍確認済=yes も弁護士操作**。
   二重ゲートに見えるが、App 43=読解の確定 / App 37=書類生成の前提確認 と役割が異なる）
 → 相続放棄ユニット（H 系列）からは 10 §5 の収集見込み・伸長検知の入力として参照
```

## 5. テスト観点（R 系列の完了条件用）

- 基本構成の導出テーブルテスト（配偶者±・子N人・尊属・兄弟・いない場合の順位繰下げ）
- 相続分の分数演算（1/2×1/3 等の厳密比較・浮動小数不使用の検証）
- 複雑ケース8フラグの検知テスト（各1ケース以上）と App 37 反映ブロック
- 前提条件（死亡未確定・名寄せ未確定・生死不明）での導出保留
- 導出ロジックのケース集は**弁護士レビューを完了条件に含める**（法的判断の焼き込みに当たるため・相続放棄 H5 の期日計算と同じ扱い）
