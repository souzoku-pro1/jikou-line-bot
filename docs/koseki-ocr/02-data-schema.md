## 3. 読解 JSON スキーマ（App 44 `読解JSON`・AI 出力の形式）

```json
{
  "様式": "改製原（昭和）", "様式confidence": 0.9,
  "戸籍": {"本籍": "...", "筆頭者": "...", "編製日": "...", "編製事由": "...",
           "従前戸籍": {"本籍": "...", "筆頭者": "..."}, "confidence": {...}},
  "人物": [
    {"氏名": "山田太郎", "続柄": "長男", "生年月日": "昭和10年3月15日",
     "除籍済み": true, "除籍事由": "婚姻",
     "身分事項": [
       {"種別": "出生", "日付": "昭和10年3月15日", "confidence": 0.95},
       {"種別": "婚姻", "日付": "...", "相手方": "佐藤花子", "confidence": 0.7},
       {"種別": "死亡", "日付": "...", "confidence": 0.9}
     ],
     "confidence": {"氏名": 0.6, "生年月日": 0.9}}
  ]
}
```

- 身分事項の `種別` 許容値: 出生 / 婚姻 / 離婚 / 養子縁組 / 離縁 / 認知 / 死亡 / 転籍 /
  入籍 / 除籍 / 改製 / その他（その他は原文を備考に保持）
- 日付は**和暦原文のまま**保持し、西暦変換（DATE 型への転記）は確認 UI での確定時に実施
  （変換誤りも人の確認対象に含める）

## 4. 名寄せ（戸籍間の同一人物統合）

```
確認済の戸籍が増えるたびに:
 1. 機械が候補提示: 氏名_正字＋生年月日の一致（±続柄の整合）で既存人物との統合候補を提示
 2. 人が確定: 確認 UI 上で「同一人物として統合 / 別人として新規」を選択 → 名寄せ確定=確定
 3. 統合時: 登場戸籍 SUBTABLE に行追加・身分事項をマージ（重複行は記載元戸籍IDで区別）
```

- 名寄せを機械確定しない理由: 同姓同名・改名・旧字体化けによる誤統合は相続人確定を
  直接誤らせる（安全側 = 人の1クリックを挟む）
